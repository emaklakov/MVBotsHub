# Localization

**Документ:** `docs/domain/localization.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`Localization` — внутренний механизм предметной области MVBotsHub, отвечающий за работу с многоязычным содержимым.

Он обеспечивает поддержку нескольких языков в рамках одного `Bot`, хранение переводов, получение локализованного значения и fallback на исходное содержимое.

`Localization` не является отдельным пользовательским рабочим пространством. Переводы редактируются непосредственно в контексте объекта, которому принадлежит текст.

---

# Ответственность

Localization отвечает за:

* поддерживаемые языки конкретного Bot;
* язык по умолчанию Bot;
* хранение локализованных значений;
* получение значения для заданного языка;
* fallback на исходное содержимое;
* определение наличия перевода;
* вычисление полноты локализации;
* предоставление локализованного содержимого runtime-компонентам.

Localization не отвечает за:

* идентификацию `Person`;
* хранение пользовательского выбора языка;
* выполнение Flow;
* выполнение Broadcast;
* отправку сообщений;
* работу с Telegram API;
* пользовательский интерфейс редакторов.

---

# Языки Bot

Каждый `Bot` имеет собственный набор поддерживаемых языков.

Пример:

```text
Bot: Support

Поддерживаемые языки:

ru
kk
en
```

Один из поддерживаемых языков является языком по умолчанию:

```text
default_language = ru
```

Язык по умолчанию относится к `Bot` и используется как общее значение для участников, у которых нет подходящего пользовательского языка.

---

# Код языка

Каждый язык идентифицируется стабильным кодом.

Например:

```text
ru
en
kk
de
```

Код языка является техническим идентификатором и не зависит от отображаемого названия.

Например:

```text
ru → Русский
en → English
kk → Қазақша
```

Название языка может изменяться без изменения его кода.

---

# Язык пользователя

Язык не является свойством `Person`.

Один и тот же `Person` может использовать разные языки в разных `Bot`.

```text
Person
   │
   ├── BotMember A
   │      └── preferred_language = ru
   │
   └── BotMember B
          └── preferred_language = en
```

Пользовательское предпочтение языка хранится в `BotMemberPreferences`.

---

# Эффективный язык

Перед выполнением Flow или формированием локализованного сообщения определяется эффективный язык текущего `BotMember`.

Порядок определения:

```text
BotMemberPreferences.preferred_language
                │
                ▼
       Язык поддерживается Bot?
             │
        ┌────┴────┐
        │         │
       Да        Нет / Не задан
        │         │
        ▼         ▼
Использовать   Bot.default_language
```

Если пользовательский язык не задан, используется язык по умолчанию `Bot`.

Если ранее выбранный язык больше не поддерживается `Bot`, используется язык по умолчанию.

Эта логика разрешается до уровня runtime. `NodeHandler` и другие исполнители не должны самостоятельно реализовывать выбор эффективного языка.

---

# Исходное содержимое

Каждый локализуемый объект имеет исходное содержимое.

Например:

```text
Язык по умолчанию Bot: ru

Текст:
Здравствуйте!
```

Исходное содержимое является обязательным fallback-значением.

Переводы являются локализованными вариантами этого содержимого.

---

# Локализуемые объекты

Localization может использоваться для:

* текстов `Flow Node`;
* текстов и подписей кнопок;
* содержимого `Broadcast`;
* системных сообщений `Bot`;
* шаблонов;
* других объектов, для которых требуется многоязычное представление.

Конкретный объект определяет, какие его поля являются локализуемыми.

---

# Редактирование переводов

Переводы редактируются непосредственно в контексте объекта.

Например, в Flow Editor:

```text
Node: welcome

Русский:
Здравствуйте!

English:
Hello!

Қазақша:
Сәлем!
```

Для `Broadcast`:

```text
Основной текст:
Новая акция!

English:
New promotion!

Қазақша:
Жаңа акция!
```

Для системного сообщения `Bot`:

```text
bot.welcome

Русский:
Добро пожаловать!

English:
Welcome!

Қазақша:
Қош келдіңіз!
```

Отдельный раздел админки для ручного поиска и редактирования переводов не требуется.

---

# Localization как внутренний механизм

Пользователь работает с бизнес-объектом:

```text
Flow
Broadcast
Bot Settings
```

а не с сущностью `Localization` как самостоятельным рабочим пространством.

Localization предоставляет внутренние механизмы хранения и разрешения переводов.

---

# Ключ локализации

Для системных сообщений и других объектов, которым нужен стабильный идентификатор содержимого, может использоваться ключ.

Примеры:

```text
bot.welcome
bot.unknown-command
bot.phone-request
bot.error
```

Ключ идентифицирует локализуемое содержимое и не содержит сам перевод.

---

# Fallback

При запросе локализованного значения используется следующий порядок:

```text
Effective Language
        │
        ▼
Перевод существует?
        │
   ┌────┴────┐
   │         │
  Да        Нет
   │         │
   ▼         ▼
Translation  Исходное содержимое
```

Если перевод отсутствует, используется исходное содержимое.

Fallback не должен приводить к потере сообщения.

---

# Полнота локализации

Система должна уметь вычислять готовность переводов.

Например, `Bot` поддерживает:

```text
ru
en
kk
de
```

а для конкретного объекта заполнены:

```text
ru
en
```

Результат:

```text
2 / 4

50%
```

---

# Состояние локализации

Состояние локализации вычисляется динамически и не хранится отдельным полем.

Используются следующие логические состояния:

```text
Не переведено
Частично переведено
Полностью переведено
```

Не допускается отдельное поле вида:

```text
translation_status
```

Источником истины являются фактически существующие переводы и список поддерживаемых языков `Bot`.

---

# Локализация Flow

Для `Flow` система может вычислять состояние локализации по всем локализуемым элементам.

Например:

```text
Flow: Registration

ru   100%
en    82%
kk    64%
```

Редактор также может показывать состояние отдельных Node:

```text
Node 1   🟢
Node 2   🟡
Node 3   🔴
```

Эти показатели вычисляются на основе текущего состояния переводов и не являются самостоятельными данными Domain.

---

# Локализация Broadcast

`Broadcast` использует тот же механизм.

Например:

```text
ru   100%
en    80%
kk    40%
```

Перед формированием сообщения для конкретного `BotMember` выбирается его эффективный язык.

---

# Локализация системных сообщений

Системные сообщения `Bot` также могут иметь переводы.

Например:

```text
bot.welcome
bot.unknown-command
bot.phone-request
bot.error
```

Редактирование выполняется в настройках соответствующего `Bot`.

---

# Добавление языка

При добавлении нового языка в `Bot`:

```text
ru
en
kk
de
```

новый язык автоматически становится доступен в интерфейсах редактирования локализуемого содержимого.

Не требуется вручную создавать отдельный набор объектов локализации для каждого `Flow` или `Broadcast`.

---

# Изменение языка по умолчанию

Изменение `Bot.default_language`:

* не изменяет `Person`;
* не изменяет `BotMemberPreferences`;
* не изменяет существующие переводы;
* влияет на пользователей без подходящего пользовательского языка;
* изменяет fallback по умолчанию.

---

# Отключение языка

Если язык перестаёт поддерживаться `Bot`, его существующие переводы не удаляются.

Например:

```text
Было:

ru
en
kk

Стало:

ru
en
```

Переводы `kk` сохраняются.

Если язык снова будет включён, ранее созданные переводы становятся доступными.

---

# Удаление перевода

Удаление конкретного перевода не удаляет исходное содержимое.

После удаления:

```text
Translation = отсутствует
```

и при необходимости используется:

```text
Fallback = исходное содержимое
```

---

# Runtime

Во время выполнения Flow эффективный язык уже определяется до обработки локализуемого содержимого.

`RuntimeContext` предоставляет:

```text
RuntimeContext.language
```

Например:

```text
RuntimeContext.language = kk
```

`NodeHandler` использует это значение и не реализует собственный алгоритм выбора языка.

---

# Localization и FlowVersion

Для опубликованного `FlowVersion` локализуемое содержимое должно оставаться консистентным с опубликованной версией сценария.

Изменение текущего Draft или его переводов не должно изменять уже опубликованный `FlowVersion`.

Если изменение перевода влияет на содержимое опубликованного сценария, оно проходит через обычный процесс публикации новой `FlowVersion`.

```text
Draft + translations
        │
        ▼
FlowCompiler
        │
        ▼
FlowVersion
```

Уже существующая `FlowVersion` остаётся неизменяемой.

---

# Localization и Broadcast

Для `Broadcast` локализация может изменяться до момента начала выполнения рассылки.

После начала рассылки содержимое и языковые варианты, необходимые для конкретного запуска, должны считаться зафиксированными в рамках этого выполнения.

Историческое содержание уже отправленной рассылки не должно изменяться задним числом.

---

# Производительность

Localization должна поддерживать большое количество локализуемого контента.

Для часто используемых данных допускается кэширование.

Например:

```text
FlowVersion
      │
      ▼
Localization
      │
      ▼
Cache
```

Кэширование не должно изменять правила выбора языка или fallback.

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* один `Bot` имеет один язык по умолчанию;
* `Bot` может поддерживать несколько языков;
* язык не является глобальным свойством `Person`;
* пользовательский язык хранится в контексте `BotMemberPreferences`;
* исходное содержимое существует независимо от переводов;
* отсутствие перевода допускает fallback, если политика `Bot` это разрешает;
* состояние локализации не хранится отдельным статусом;
* отключение языка не удаляет существующие переводы;
* переводы редактируются в контексте объекта, которому они принадлежат;
* опубликованный `FlowVersion` не изменяется из-за последующего редактирования текущего Draft;
* Localization не зависит от Telegram.

---

# Безопасность

Переводы являются пользовательскими данными и могут содержать чувствительное содержимое.

Поэтому:

* переводы не должны содержать секреты;
* API-токены и пароли не должны храниться в переводах;
* содержимое переводов не должно без необходимости попадать в логи;
* изменение переводов должно проходить через права доступа к соответствующему объекту.

---

# Будущие возможности

Архитектура допускает:

* автоматический перевод;
* машинный перевод с последующим подтверждением;
* переводческую память;
* массовый импорт и экспорт;
* автоматическую проверку качества переводов;
* сравнение переводов между версиями;
* внешние сервисы перевода;
* дополнительные fallback-правила;
* переводческие workflow.
