# Назначение

Подсистема **Flow** отвечает за описание, публикацию и выполнение сценариев взаимодействия пользователей с ботом.

Flow является центральной частью MVBotsHub и представляет собой Workflow Engine, предназначенный для построения сложных диалогов без программирования.

Подсистема обеспечивает:

- создание сценариев;
- редактирование сценариев;
- публикацию новых версий;
- выполнение опубликованных сценариев;
- маршрутизацию входящих событий;
- переходы между сценариями;
- выполнение сценариев с сохранением состояния пользователя.

---

# Основные принципы

Подсистема Flow построена на следующих принципах.

## Разделение описания и выполнения

Описание сценария и его выполнение являются независимыми процессами.

Сценарий описывает последовательность действий.

Flow Engine выполняет сценарий.

FlowSession хранит состояние выполнения.

---

## Версионирование

Каждая опубликованная версия сценария является неизменяемой.

После публикации изменение версии не допускается.

Любые изменения выполняются только через создание новой версии.

---

## Draft и Published

Каждый Flow существует в двух состояниях.

- Draft — редактируемая версия.
- Published (FlowVersion) — опубликованная версия.

Flow Engine никогда не выполняет Draft.

---

## Компиляция

Перед публикацией Draft проходит проверку и компиляцию.

В публикацию может попасть только корректный сценарий.

---

## JSON Graph

Структура сценария хранится в виде единого JSON-документа.

JSON содержит описание графа сценария и является единственным источником информации о структуре Flow.

---

## Универсальные узлы

Все узлы имеют одинаковую структуру.

Тип узла определяется полем `type`.

Логика выполнения определяется соответствующим `NodeHandler`.

---

## Переиспользуемые сценарии

Flow может вызывать другой Flow.

После завершения дочернего Flow выполнение возвращается в исходный Flow.

Flow рассматривается как переиспользуемый модуль.

---

## Независимость от платформы

Flow ничего не знает о Telegram.

Он работает только с доменными событиями и командами.

Telegram является одним из возможных каналов взаимодействия.

---

# Основные компоненты

| Компонент | Назначение |
|-----------|------------|
| Flow | Контейнер сценария |
| FlowDraft | Редактируемая версия сценария |
| FlowVersion | Опубликованная версия сценария |
| FlowTrigger | Точка входа в сценарий |
| FlowSession | Состояние выполнения сценария |
| FlowRouter | Выбор сценария для запуска |
| FlowCompiler | Проверка и публикация сценария |
| FlowEngine | Исполнение сценария |
| RuntimeContext | Контекст выполнения |
| NodeHandler | Обработчик конкретного типа узла |

# Переходы между сценариями

Flow может запускать другой Flow.

```text
Главное меню

        │
        ▼

Каталог

        │
        ▼

Оформление заказа

        │
        ▼

Подтверждение оплаты

        │
        ▼

Возврат

        │
        ▼

Каталог
```

Flow рассматривается как переиспользуемый модуль.

Для перехода используется узел `FlowCall`.

Возврат осуществляется автоматически после завершения дочернего Flow.

---

# FlowStack

Во время выполнения система поддерживает стек вызовов Flow.

Например:

```text
Main Menu

↓

Catalog

↓

Checkout
```

После завершения `Checkout` выполнение возвращается в `Catalog`, затем в `Main Menu`.

Такой подход позволяет строить сложные сценарии без дублирования логики.

---

# RuntimeContext

Во время выполнения каждый `NodeHandler` получает единый объект `RuntimeContext`.

Контекст содержит:

- текущий Bot;
- текущий BotMember;
- текущий Conversation;
- текущий FlowSession;
- текущий FlowVersion;
- стек вызовов Flow;
- переменные сценария;
- язык общения;
- другую служебную информацию.

Это избавляет обработчики узлов от необходимости самостоятельно искать необходимые данные.

---

# Общие правила

Подсистема Flow придерживается следующих правил.

- Draft никогда не выполняется пользователями.
- Published версия никогда не изменяется.
- Все изменения выполняются через новую версию.
- Flow может иметь несколько точек входа.
- Bot может содержать множество Flow.
- Flow может вызывать другой Flow.
- Все ссылки внутри JSON используют публичный `code`, а не идентификаторы базы данных.
- Все опубликованные версии являются неизменяемыми.
- Все проверки выполняются до публикации.
- Выполнение сценариев не зависит от Telegram.
