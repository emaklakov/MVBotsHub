# FlowVersion

**Документ:** `docs/domain/flow/flow-version.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`FlowVersion` представляет собой опубликованную неизменяемую версию сценария.

Каждая публикация `FlowDraft` создаёт новую `FlowVersion`.

После публикации версия никогда не изменяется.

Все пользовательские сессии выполняются исключительно на основе опубликованных версий.

---

# Ответственность

FlowVersion отвечает за:

- хранение опубликованной структуры сценария;
- обеспечение неизменяемости опубликованной версии;
- сохранение истории публикаций;
- предоставление данных для выполнения сценария.

FlowVersion **не отвечает** за:

- редактирование сценария;
- выполнение сценария;
- маршрутизацию;
- хранение пользовательских сессий;
- хранение черновика.

---

# Основные свойства

| Поле | Описание |
|------|----------|
| id | Внутренний идентификатор |
| flow_id | Родительский Flow |
| version | Порядковый номер публикации |
| graph_json | Полная структура опубликованного сценария |
| checksum | Контрольная сумма graph_json |
| published_by | Пользователь, выполнивший публикацию |
| published_at | Дата публикации |
| created_at | Дата создания записи |

---

# Публичный идентификатор версии

Каждая опубликованная версия имеет удобное публичное представление.

Формат:

```text
flow_code@version
```

Например:

```text
main-menu@1
registration@3
checkout@7
support@12
```

Это представление используется:

- в документации;
- в логах;
- при импорте и экспорте;
- в сообщениях об ошибках;
- в инструментах диагностики.

Данный идентификатор не хранится в базе данных и формируется динамически из полей `Flow.code` и `FlowVersion.version`.

---

# Неизменяемость

После публикации FlowVersion становится неизменяемой.

Не допускается изменение:

- graph_json;
- version;
- checksum;
- published_by;
- published_at.

Любое изменение сценария приводит к созданию новой FlowVersion.

---

# История публикаций

Каждый Flow может иметь неограниченное количество опубликованных версий.

```text
Flow

├── Version 1

├── Version 2

├── Version 3

└── Version 4
```

История публикаций никогда не удаляется.

---

# Активная версия

Flow хранит ссылку на текущую опубликованную версию.

```text
Flow

↓

active_version_id

↓

FlowVersion
```

Одновременно активной может быть только одна версия.

При публикации новой версии ссылка обновляется автоматически.

---

# Структура сценария

Поле `graph_json` содержит полную опубликованную структуру сценария.

В него входят:

- узлы;
- связи;
- параметры узлов;
- настройки сценария;
- служебные данные, необходимые для выполнения.

После публикации содержимое `graph_json` никогда не изменяется.

---

# Нумерация версий

Каждая публикация увеличивает номер версии.

```text
1

↓

2

↓

3

↓

4
```

Нумерация всегда возрастает.

Пропуски номеров не допускаются.

Версии никогда не переиспользуются.

---

# Контрольная сумма

Поле `checksum` содержит контрольную сумму опубликованного `graph_json`.

Используется для:

- проверки целостности данных;
- контроля импорта и экспорта;
- диагностики;
- обнаружения повреждений данных.

---

# Публикация

FlowVersion создаётся только в процессе публикации Draft.

Процесс публикации выполняется в рамках одной транзакции.

```text
FlowDraft
        │
        ▼
FlowCompiler
        │
        ▼
Validation
        │
        ▼
Создание FlowVersion
        │
        ▼
Обновление Flow.active_version_id
        │
        ▼
Обновление FlowDraft.published_version_id
        │
        ▼
Commit
```

Если любой этап завершается ошибкой, транзакция полностью откатывается.

---

# Выполнение сценария

Все новые пользовательские сессии создаются на основе активной FlowVersion.

```text
Flow

↓

FlowVersion

↓

FlowSession

↓

FlowEngine
```

После запуска FlowSession продолжает использовать ту версию сценария, с которой была создана.

Даже если опубликована новая версия, уже выполняющиеся сценарии не переключаются автоматически.

---

# Совместное существование версий

Несколько опубликованных версий одного Flow могут существовать одновременно.

Например:

```text
checkout@5
```

используется выполняющейся FlowSession.

В это же время

```text
checkout@6
```

уже становится активной версией для новых пользователей.

Это гарантирует стабильность выполнения сценариев.

---

# Повторная публикация

Каждая публикация всегда создаёт новую FlowVersion.

Даже если изменения минимальны или отсутствуют, существующая версия никогда не изменяется.

---

# Удаление

FlowVersion не удаляется.

Даже после архивирования или мягкого удаления Flow все опубликованные версии сохраняются.

Это необходимо для:

- аудита;
- истории выполнения;
- анализа ошибок;
- восстановления данных.

---

# Инварианты

Всегда должны соблюдаться следующие правила.

- FlowVersion является неизменяемой.
- Каждая публикация создаёт новую FlowVersion.
- Версия принадлежит одному Flow.
- `graph_json` никогда не изменяется после публикации.
- Все FlowSession используют только FlowVersion.
- Одновременно активной может быть только одна версия.
- История публикаций никогда не удаляется.
- Публичный идентификатор версии формируется как `flow_code@version`.

---

# Будущие возможности

Архитектура допускает дальнейшее развитие.

Например:

- комментарии к публикации;
- журнал изменений;
- сравнение двух опубликованных версий;
- откат Flow к предыдущей версии;
- экспорт конкретной версии;
- импорт опубликованной версии;
- цифровая подпись опубликованных сценариев.
