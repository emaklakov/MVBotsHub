# FlowDraft

**Документ:** `docs/domain/flow/flow-draft.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`FlowDraft` представляет собой единственную редактируемую версию сценария.

Каждый `Flow` всегда имеет один `FlowDraft`.

Draft используется исключительно редактором сценариев и никогда не участвует в выполнении сценариев пользователями.

Все изменения сценария производятся только через Draft.

---

# Ответственность

FlowDraft отвечает за:

- хранение редактируемого графа сценария;
- автосохранение изменений;
- хранение состояния визуального редактора;
- хранение информации о последней проверке;
- подготовку сценария к публикации.

FlowDraft **не отвечает** за:

- выполнение сценария;
- публикацию;
- хранение истории выполнения;
- маршрутизацию событий;
- выполнение узлов;
- взаимодействие с Telegram.

---

# Основные свойства

| Поле | Описание |
|------|----------|
| id | Внутренний идентификатор |
| flow_id | Родительский Flow |
| published_version_id | Версия, на основе которой создан Draft |
| graph_json | JSON-граф сценария |
| editor_version | Версия формата редактора |
| revision | Номер ревизии Draft |
| viewport | Положение камеры редактора |
| editor_settings | Настройки редактора |
| validation_state | Последний результат проверки |
| updated_by | Пользователь, внесший последнее изменение |
| created_at | Дата создания |
| updated_at | Дата изменения |

# Один Draft на один Flow

Каждый Flow всегда имеет только один Draft.

```text
Flow
 │
 ▼
FlowDraft
```

Создание нескольких Draft для одного Flow не допускается.

После публикации Draft продолжает существовать и используется для дальнейшего редактирования.

---

# Связь с опубликованной версией

Каждый Draft создаётся на основе определённой опубликованной версии Flow.

Поле `published_version_id` хранит ссылку на эту версию.

```text
FlowVersion v12
        │
        ▼
     FlowDraft
```

После публикации новой версии связь автоматически обновляется.

```text
FlowVersion v13
        │
        ▼
     FlowDraft
```

Если опубликованных версий ещё нет, значение `published_version_id` равно `null`.

Это позволяет:

- определить базовую версию Draft;
- сравнить Draft с опубликованной версией;
- показать список изменений перед публикацией;
- откатить Draft к опубликованной версии;
- реализовать визуальный Diff.

---

# graph_json

Поле `graph_json` является единственным источником информации о структуре сценария.

Внутри JSON содержатся:

- узлы;
- связи между узлами;
- параметры узлов;
- локальные настройки сценария;
- служебные данные графа.

FlowDraft не хранит структуру сценария в отдельных таблицах базы данных.

---

# editor_version

Определяет формат данных редактора.

Например:

```text
1
```

Если в будущих версиях платформы структура JSON изменится, система сможет автоматически выполнить миграцию Draft.

---

# revision

Каждое успешное сохранение увеличивает номер ревизии.

```text
1

↓

2

↓

3

↓

4
```

Используется для оптимистичной блокировки при одновременном редактировании.

---

# viewport

Хранит положение редактора.

Например:

```json
{
    "x": 1280,
    "y": -420,
    "zoom": 0.85
}
```

При повторном открытии сценария пользователь возвращается к последнему месту работы.

---

# editor_settings

Хранит пользовательские настройки редактора.

Например:

```json
{
    "grid": true,
    "snap": true,
    "minimap": false
}
```

Эти параметры относятся только к интерфейсу редактора и не влияют на выполнение сценария.

---

# validation_state

Хранит результат последней проверки Draft.

Возможные состояния:

- Valid
- Warnings
- Errors

Это позволяет отображать состояние сценария без повторного запуска полной проверки.

---

# Автосохранение

Редактор автоматически сохраняет изменения.

```text
Изменение

↓

Автосохранение

↓

FlowDraft
```

Период автосохранения определяется настройками редактора.

Пользователь не обязан выполнять сохранение вручную.

---

# Незавершённые сценарии

Draft может находиться в невалидном состоянии.

Например:

- отсутствуют обязательные параметры;
- отсутствует следующий узел;
- имеются недостижимые узлы;
- отсутствуют переводы;
- имеются предупреждения проверки.

Во время редактирования это считается нормальным состоянием.

Ошибкой это становится только при публикации.

---

# Sandbox

Draft может выполняться только в режиме Sandbox.

```text
FlowDraft

↓

Sandbox

↓

FlowEngine
```

Sandbox использует Draft напрямую и никак не влияет на опубликованные версии.

---

# Компиляция

Перед публикацией Draft всегда передаётся в `FlowCompiler`.

```text
FlowDraft

↓

FlowCompiler

↓

Validation Report

↓

FlowVersion
```

Draft никогда не становится опубликованной версией напрямую.

---

# Публикация

Публикация является атомарной операцией.

Во время публикации выполняется одна транзакция.

```text
FlowDraft
        │
        ▼
FlowCompiler
        │
        ▼
Validation
        │
        ▼
Создание FlowVersion
        │
        ▼
Обновление Flow.active_version_id
        │
        ▼
Обновление FlowDraft.published_version_id
        │
        ▼
Commit
```

Если любой этап завершается ошибкой, вся операция отменяется.

---

# Конфликты редактирования

Если Draft открыт несколькими пользователями одновременно, используется оптимистичная блокировка.

Перед сохранением проверяется поле `revision`.

Если Draft был изменён другим пользователем, сохранение отклоняется.

Редактор должен предложить пользователю:

- обновить Draft;
- просмотреть изменения;
- повторить редактирование.

---

# Удаление

FlowDraft не существует отдельно от Flow.

При удалении или восстановлении Flow соответствующие действия автоматически применяются и к Draft.

Отдельное удаление Draft невозможно.

---

# Инварианты

Всегда должны соблюдаться следующие правила.

- Каждый Flow имеет один Draft.
- Draft никогда не используется пользователями.
- Draft никогда не является опубликованной версией.
- Все изменения сценария выполняются только через Draft.
- Draft может находиться в невалидном состоянии.
- Draft может выполняться только в Sandbox.
- `graph_json` является единственным источником структуры сценария.
- Каждая публикация создаёт новую FlowVersion.
- Автосохранение не создаёт новые версии сценария.
- Draft всегда знает, относительно какой опубликованной версии он создан.

---

# Будущие возможности

Архитектура допускает дальнейшее развитие без изменения модели.

Например:

- совместное редактирование;
- комментарии к узлам;
- история изменений Draft;
- визуальное сравнение Draft и опубликованной версии;
- откат Draft к опубликованной версии;
- ветвление Draft;
- автоматическое разрешение конфликтов.
