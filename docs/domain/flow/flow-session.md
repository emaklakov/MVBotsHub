# FlowSession

**Документ:** `docs/domain/flow/flow-session.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`FlowSession` представляет собой состояние выполнения опубликованного `Flow` для конкретного `BotMember`.

FlowSession является агрегатом, который отвечает за жизненный цикл конкретного экземпляра выполнения сценария.

Один и тот же `Flow` может одновременно выполняться в большом количестве независимых FlowSession.

FlowSession всегда выполняется относительно конкретной `FlowVersion`.

---

# Ответственность

FlowSession отвечает за:

- хранение текущего состояния выполнения;
- хранение ссылки на выполняемую `FlowVersion`;
- хранение текущей позиции выполнения;
- хранение стека вызовов Flow;
- хранение переменных выполнения;
- хранение состояния ожидания;
- приостановку и возобновление выполнения;
- завершение выполнения Flow.

FlowSession не отвечает за:

- редактирование Flow;
- публикацию FlowVersion;
- маршрутизацию внешних событий;
- отправку сообщений;
- работу с Telegram API;
- хранение постоянных данных Person;
- хранение пользовательских предпочтений BotMember.

---

# Принадлежность

FlowSession всегда относится к конкретному `BotMember`.

```text
BotMember
    │
    └── FlowSession
```

При этом одна FlowSession выполняет конкретный Flow.

```text
Flow
    │
    ▼
FlowVersion
    │
    ▼
FlowSession
```

---

# Основные свойства

| Поле | Описание |
|------|----------|
| id | Внутренний идентификатор |
| bot_member_id | Участник Bot, для которого выполняется сценарий |
| flow_id | Flow, с которого началось выполнение |
| flow_version_id | Версия Flow, используемая выполнением |
| status | Текущее состояние FlowSession |
| current_node | Текущая позиция выполнения |
| stack | Стек вызовов Flow |
| variables | Переменные выполнения |
| waiting_state | Состояние ожидания |
| started_at | Время начала |
| paused_at | Время приостановки |
| finished_at | Время завершения |
| created_at | Дата создания |
| updated_at | Дата изменения |

Конкретный способ хранения этих данных определяется инфраструктурным слоем.

---

# Связь с FlowVersion

FlowSession всегда фиксирует конкретную `FlowVersion`.

Например:

```text
registration@7
        │
        ▼
FlowSession #12501
```

Если позднее публикуется:

```text
registration@8
```

существующая FlowSession продолжает работать с:

```text
registration@7
```

Автоматическое переключение активной сессии на новую версию не выполняется.

---

# Начало выполнения

FlowSession создаётся после того, как `FlowRouter` определил Flow и выбрал опубликованную версию для выполнения.

```text
Incoming Event

↓

FlowRouter

↓

FlowTrigger

↓

Flow

↓

Active FlowVersion

↓

FlowSession
```

После создания FlowSession дальнейшее выполнение выполняет `FlowEngine`.

---

# Жизненный цикл

```text
Created

↓

Running

↓

Waiting

↓

Running

↓

Completed
```

Также возможны состояния:

```text
Paused
Cancelled
Failed
```

---

# Created

FlowSession создана, но выполнение ещё не началось.

---

# Running

FlowSession активно выполняется.

В этом состоянии `FlowEngine` может обрабатывать текущий Node и последовательно выполнять синхронные действия.

---

# Waiting

FlowSession временно приостановлена и ожидает внешнего события.

Например:

- сообщение пользователя;
- нажатие кнопки;
- получение контакта;
- получение геолокации;
- завершение задержки;
- завершение внешнего запроса;
- подтверждение оплаты.

Ожидание должно быть явно описано в `waiting_state`.

---

# Paused

Выполнение временно приостановлено без завершения FlowSession.

Используется для системных или административных сценариев, когда дальнейшее выполнение должно быть возобновлено позже.

---

# Completed

FlowSession успешно завершена.

После этого она больше не исполняется.

---

# Cancelled

Выполнение было остановлено до нормального завершения.

Например:

- пользователь покинул сценарий;
- выполнение было отменено системой;
- Flow был остановлен;
- оператор принудительно завершил выполнение.

---

# Failed

Выполнение завершилось ошибкой, которую система не смогла обработать автоматически.

Причина ошибки должна быть зафиксирована в служебной истории выполнения.

---

# Текущая позиция

FlowSession хранит информацию о текущем узле выполнения.

```text
FlowVersion
    │
    ▼
Current Node
```

После успешной обработки узла текущая позиция обновляется.

FlowSession никогда не изменяет сам `FlowVersion`.

---

# FlowStack

FlowSession поддерживает стек вызовов Flow.

Например:

```text
Main Menu

↓

Catalog

↓

Checkout
```

Текущий Flow:

```text
Checkout
```

После завершения `Checkout` выполнение возвращается в:

```text
Catalog
```

После завершения `Catalog`:

```text
Main Menu
```

---

# Назначение FlowStack

FlowStack позволяет:

- переиспользовать отдельные Flow;
- вызывать один сценарий из другого;
- возвращаться в исходный сценарий;
- не дублировать одинаковую логику.

Переход выполняется через `FlowCall`.

---

# Состояние стека

Для каждого уровня стека должны сохраняться данные, необходимые для возврата.

Например:

```text
Frame #1
Flow: main-menu

Frame #2
Flow: catalog

Frame #3
Flow: checkout
```

Текущий Frame является активным.

После завершения Frame управление возвращается предыдущему Frame.

---

# Переменные

FlowSession хранит переменные, относящиеся только к текущему выполнению.

Например:

```text
selected_product
verification_code
current_step
attempt_count
```

Эти переменные не являются постоянными данными BotMember.

Постоянные пользовательские данные хранятся отдельно в рамках BotMember и соответствующих настроек или переменных участника.

---

# Waiting State

Когда Node требует ожидания внешнего события, FlowSession переходит в состояние `Waiting`.

Например:

```text
Input Text

↓

Waiting

↓

Message Received

↓

Running
```

`waiting_state` должен содержать достаточно информации для определения события, которое может возобновить выполнение.

---

# Пример ожидания

```json
{
    "type": "message",
    "expected": "text",
    "node": "ask-name"
}
```

После получения подходящего события FlowEngine продолжает выполнение с ожидаемого состояния.

---

# Возобновление

FlowSession может быть возобновлена после получения:

- сообщения;
- callback;
- контакта;
- другого подходящего доменного события;
- системного сигнала;
- результата отложенной операции.

Обработка события должна быть идемпотентной.

Повторная доставка одного и того же события не должна приводить к повторному выполнению уже завершённого шага.

---

# Связь с Conversation

FlowSession связана с текущим контекстом общения, но не является заменой `Conversation`.

`Conversation` отвечает за сеанс общения и историю сообщений.

`FlowSession` отвечает за выполнение сценария.

Эти сущности имеют разные жизненные циклы и не должны смешиваться.

Одна Conversation может последовательно использовать несколько FlowSession.

Внутри одной Conversation FlowSession может завершиться, после чего будет запущена другая FlowSession.

---

# Завершение

FlowSession считается завершённой, когда:

- достигнут конечный узел;
- Flow завершён системой;
- выполнение отменено;
- выполнение завершилось необрабатываемой ошибкой.

После завершения FlowSession не может быть возобновлена как активное выполнение.

---

# Инварианты

Всегда должны соблюдаться следующие правила.

- FlowSession принадлежит одному BotMember.
- FlowSession выполняет конкретную FlowVersion.
- FlowVersion после создания FlowSession не изменяется.
- FlowSession не изменяет FlowVersion.
- Одна FlowSession не может одновременно находиться в нескольких состояниях.
- Завершённая FlowSession не исполняется повторно.
- FlowStack всегда имеет однозначно определённый текущий Frame.
- Состояние ожидания должно быть достаточно точным для безопасного возобновления.
- Повторная обработка одного внешнего события не должна приводить к дублированию результата.

---

# Обработка ошибок

Если Node не может быть выполнен:

1. ошибка фиксируется;
2. FlowEngine определяет, может ли ошибка быть обработана Flow;
3. при наличии соответствующего механизма выполняется обработка ошибки;
4. при невозможности восстановления FlowSession переходит в `Failed`.

FlowSession не должна silently продолжать выполнение после неизвестной ошибки.

---

# Масштабирование

Архитектура FlowSession должна позволять:

- одновременно выполнять один Flow для большого количества BotMember;
- быстро восстанавливать состояние после перезапуска воркера;
- безопасно передавать выполнение между очередями;
- возобновлять выполнение после длительного ожидания;
- хранить состояние независимо от процесса, который выполняет FlowEngine.

Состояние FlowSession не должно зависеть от памяти конкретного PHP-процесса.

---

# Принцип персистентности состояния

Текущее состояние FlowSession ДОЛЖНО быть сохранено во внешнем хранилище до момента, когда выполнение считается безопасно продолженным.

Это позволяет:

- пережить перезапуск worker;
- перенести выполнение на другой worker;
- возобновить сценарий после временного сбоя;
- не зависеть от локальной памяти процесса.

---

# Будущие возможности

Архитектура допускает развитие:

- возобновление сценария после длительного простоя;
- приоритетное выполнение;
- ручное вмешательство оператора;
- отладку FlowSession;
- пошаговое воспроизведение;
- повторный запуск отдельного Frame;
- аудит выполнения каждого Node.
