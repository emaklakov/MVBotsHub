# Flow

**Документ:** `docs/domain/flow/flow.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`Flow` представляет собой сценарий взаимодействия между ботом и пользователем.

Flow является корневым агрегатом подсистемы сценариев и объединяет все сущности, необходимые для создания, публикации и выполнения сценария.

Сам Flow **не содержит структуру сценария**, **не выполняется** и **не хранит состояние выполнения**. Эти обязанности делегированы специализированным компонентам подсистемы Flow.

---

# Ответственность

Flow отвечает за управление жизненным циклом сценария.

В его обязанности входит:

- создание нового сценария;
- хранение основной информации;
- управление черновиком;
- управление опубликованными версиями;
- управление точками входа;
- управление состоянием сценария;
- предоставление активной опубликованной версии.

Flow не отвечает за:

- выполнение сценария;
- хранение графа;
- выполнение узлов;
- обработку событий;
- хранение пользовательского состояния;
- взаимодействие с Telegram и другими каналами.

---

# Основные свойства

| Поле | Описание |
|------|----------|
| id | Внутренний идентификатор |
| bot_id | Бот-владелец |
| code | Уникальный публичный идентификатор |
| name | Название сценария |
| description | Краткое описание |
| sort | Порядок отображения внутри Bot |
| status | Текущее состояние |
| active_version_id | Активная опубликованная версия |
| created_at | Дата создания |
| updated_at | Дата изменения |
| deleted_at | Дата мягкого удаления |

---

# Назначение полей

## code

`code` является публичным идентификатором сценария.

Например:

```text
main-menu
registration
checkout
support
language-selection
```

Используется:

- внутри JSON;
- в API;
- при импорте и экспорте;
- при выполнении `FlowCall`.

Внутренний `id` никогда не используется за пределами слоя хранения данных.

---

## sort

Определяет порядок отображения сценариев внутри Bot.

Поле используется исключительно пользовательским интерфейсом и не влияет на выполнение сценариев.

---

## status

Определяет текущее состояние жизненного цикла Flow.

---

# Жизненный цикл

```text
           Active
              │
              ▼
          Disabled
              │
              ▼
          Archived
              │
              ▼
           Deleted
```

## Active

Сценарий доступен для запуска.

---

## Disabled

Сценарий временно отключён.

Запуск новых FlowSession запрещён.

---

## Archived

Сценарий завершил жизненный цикл, но полностью сохраняется.

Не отображается в рабочих списках.

Может быть восстановлен.

---

## Deleted

Мягкое удаление.

Физически запись не удаляется.

Используется исключительно Soft Delete.

---

# Состав агрегата

Flow объединяет следующие сущности.

```text
Flow

├── FlowDraft (1)

├── FlowVersion (1..N)

└── FlowTrigger (0..N)
```

Каждая сущность имеет собственную ответственность и описывается отдельным документом.

---

# Связь с Bot

Каждый Flow принадлежит одному Bot.

```text
Bot

└── Flow
```

Bot может содержать любое количество сценариев.

---

# Независимость сценариев

Flow независимы друг от друга.

Связь между ними создаётся исключительно через `FlowCall`.

---

# Запуск сценария

Flow никогда не запускается напрямую.

```text
Событие

↓

FlowRouter

↓

FlowTrigger

↓

Flow
```

---

# Выполнение сценария

Flow не хранит состояние выполнения.

Каждое выполнение создаёт собственную FlowSession.

```text
Flow

↓

FlowSession

↓

FlowEngine
```

Благодаря этому тысячи пользователей могут одновременно выполнять один и тот же сценарий.

---

# Работа с версиями

Flow не хранит граф сценария.

Граф хранится только в:

- FlowDraft;
- FlowVersion.

Flow содержит ссылку только на активную опубликованную версию.

---

# Переходы между сценариями

Flow может вызывать другой Flow.

```text
Main Menu

↓

Checkout

↓

Payment

↓

Return

↓

Main Menu
```

Для этого используется узел `FlowCall`.

Возврат выполняется автоматически посредством стека вызовов Flow.

---

# Инварианты

Всегда должны соблюдаться следующие правила.

- Flow принадлежит одному Bot.
- `code` уникален в пределах Bot.
- Активной может быть только одна опубликованная версия.
- Каждый Flow имеет один Draft.
- Flow не содержит граф сценария.
- Flow не содержит пользовательского состояния.
- Flow не зависит от Telegram.
- Все ссылки используют `code`, а не `id`.
- Flow никогда не удаляется физически.
- Опубликованные версии являются неизменяемыми.

---

# Создание

При создании автоматически создаются:

- Flow;
- пустой FlowDraft.

Опубликованные версии отсутствуют.

---

# Архивация

Архивация используется для завершённых сценариев.

После архивации:

- новые выполнения невозможны;
- Draft сохраняется;
- все версии сохраняются;
- Trigger сохраняются;
- сценарий можно восстановить.

---

# Удаление

Flow использует Soft Delete.

После удаления:

- сценарий скрывается;
- новые выполнения запрещены;
- история полностью сохраняется;
- опубликованные версии сохраняются.

Физическое удаление агрегата не выполняется.

---

# Восстановление

После восстановления:

- Draft остаётся;
- FlowVersion остаются;
- FlowTrigger остаются;
- сценарий может быть снова переведён в состояние Active.

---

# Ограничения

Flow нельзя архивировать или удалить, если:

- существуют активные FlowSession;
- опубликованные сценарии содержат ссылки на данный Flow.

Подобные операции должны быть отклонены системой.

---

# Будущие возможности

Архитектура допускает развитие без изменения модели Flow.

Например:

- шаблоны сценариев;
- библиотека Flow;
- маркетплейс;
- публикация по расписанию;
- совместное редактирование;
- клонирование;
- импорт и экспорт.
