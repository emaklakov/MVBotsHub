# Bots

**Документ:** `docs/admin/bots.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

Настоящий документ описывает административное управление `Bot` в MVBotsHub.

Административный раздел Bots предоставляет User возможность создавать, просматривать, изменять и управлять доступными Bot в рамках предоставленных permissions и `BotAccess`.

Бизнес-модель самого Bot описана в:

`docs/domain/bot.md`

Настоящий документ описывает именно административные сценарии работы с Bot.

---

# Доступ к Bot

User может видеть и управлять только теми Bot, к которым у него есть право доступа.

В обычном режиме:

```text
User
 │
 ├── Created Bot
 │
 └── BotAccess
        │
        ▼
     Available Bots
```

Особые системные permissions могут предоставлять расширенный доступ.

---

# Создание Bot

Создание нового Bot выполняется через Application Use Case.

Общий сценарий:

```text
MoonShine
   ↓
CreateBot
   ↓
Bot
   ↓
BotSettings
   ↓
BotAccess для создателя
```

При успешном создании:

* Bot получает уникальный публичный `code`;
* создаётся обязательный набор настроек;
* создаётся доступ User, создавшему Bot;
* Bot становится доступен создавшему User.

---

# Публичный code

Каждый Bot должен иметь стабильный публичный `code`.

Он используется:

* в API;
* в импорте и экспорте;
* в интеграциях;
* в диагностике;
* в ссылках, где требуется публичный идентификатор.

Внутренний `id` базы данных не должен использоваться как единственный публичный идентификатор.

---

# Список Bot

Список Bot должен быть отфильтрован по текущему User.

Предпочтительный принцип:

```text
User
 ↓
Accessible Bots Query
 ↓
Только разрешённые Bot
```

Фильтрация должна выполняться на уровне запроса/политики доступа, а не после загрузки всех Bot в память приложения.

---

# Контекст Bot

После выбора Bot административный интерфейс работает в его контексте.

Например:

```text
MVBotsHub
    ↓
Support Bot
    ↓
Flows
Broadcasts
Conversations
Members
Settings
```

Каждый переход к дочернему ресурсу должен проверять, что ресурс действительно принадлежит выбранному Bot.

---

# Основные операции

Административная подсистема может предоставлять следующие операции:

```text
View
Create
Update
Disable
Archive
Restore
Delete (Soft Delete)
```

Конкретная доступность операции определяется permissions.

---

# Статус Bot

Жизненный цикл Bot управляется самим агрегатом Bot.

Административная панель должна отображать состояние Bot и выполнять только допустимые переходы.

Например:

```text
Active
Disabled
Archived
Deleted
```

Фактический набор состояний и переходов является частью бизнес-модели `Bot`.

---

# Редактирование Bot

Изменение данных Bot выполняется через Application Use Case.

Например:

```text
MoonShine
   ↓
UpdateBot
   ↓
Bot
```

Presentation не должен содержать самостоятельную бизнес-логику изменения Bot.

---

# BotSettings

Настройки общего поведения Bot редактируются через административный интерфейс в контексте Bot.

```text
Bot
 ↓
Settings
 ↓
BotSettings
```

Пользовательские настройки конкретного `BotMember` не должны редактироваться через BotSettings.

Подробная модель:

`docs/domain/bot-settings.md`

---

# Localization

Настройки языков и локализуемое системное содержимое могут редактироваться в контексте Bot.

Например:

```text
Bot
 ↓
Languages
 ↓
System Messages
```

Пользователь не должен переходить в отдельный глобальный раздел Localization для изменения текста конкретного Bot.

Подробная модель:

`docs/domain/localization.md`

---

# Flows

Раздел Flows предоставляет управление сценариями выбранного Bot.

Например:

```text
Bot
 ↓
Flows
 ├── Main Menu
 ├── Registration
 ├── Help
 └── Checkout
```

Доступные операции определяются permissions:

```text
flow.view
flow.update
flow.publish
```

Подробная архитектура Flow описана в:

`docs/domain/flow/README.md`

---

# Broadcasts

Раздел Broadcasts предоставляет управление рассылками выбранного Bot.

Доступны операции в пределах permissions User, например:

```text
broadcast.view
broadcast.create
broadcast.update
broadcast.send
broadcast.cancel
```

Бизнес-модель Broadcast описана в:

`docs/domain/broadcast.md`

---

# Conversations

Администратор может просматривать Conversation только при наличии соответствующего права.

Например:

```text
conversation.view
```

Все Conversation должны автоматически фильтроваться по Bot.

Изменение исторических сообщений через обычный административный интерфейс не допускается.

---

# BotMember

Раздел Members предоставляет просмотр и, при наличии прав, изменение данных участников выбранного Bot.

```text
Bot
 ↓
Members
 ↓
BotMember
```

Доступ к персональным данным должен дополнительно учитывать требования безопасности и privacy policy проекта.

---

# BotAccess

Раздел Access позволяет управлять User, имеющими доступ к текущему Bot.

Например:

```text
Bot
 ↓
Access
 ├── User A → Owner
 ├── User B → Operator
 └── User C → Analyst
```

Управление требует соответствующих permissions:

```text
bot-access.view
bot-access.grant
bot-access.update
bot-access.revoke
```

---

# Удаление

Административная кнопка `Delete` не должна приводить к физическому удалению Bot.

Используется Soft Delete или соответствующий жизненный цикл Bot.

После удаления:

* Bot перестаёт отображаться в обычных списках;
* новые операции запрещаются;
* история и связанные данные сохраняются в соответствии с политикой хранения.

---

# Восстановление

User с соответствующим permission может восстановить удалённый или архивированный Bot, если бизнес-правила позволяют это.

При восстановлении сохраняются:

* BotSettings;
* Flows;
* FlowVersions;
* Broadcast history;
* Conversations;
* BotMembers;
* BotAccess.

Восстановление не должно автоматически изменять исторические данные.

---

# Безопасность

Каждая административная операция над Bot должна проходить серверную авторизацию.

Минимальный принцип:

```text
Authenticated User
        ↓
Global Permission
        ↓
BotAccess
        ↓
Operation Permission
        ↓
Resource Check
        ↓
Execute
```

Скрытие кнопки в MoonShine не является механизмом безопасности.

---

# Аудит

Критические операции над Bot должны фиксироваться в административном аудите.

Например:

```text
Create Bot
Update Bot
Disable Bot
Archive Bot
Restore Bot
Delete Bot
Grant Access
Revoke Access
Publish Flow
Send Broadcast
```

Аудит должен фиксировать User, Bot, операцию, время и результат.

---

# Notifications

Некоторые административные операции могут создавать уведомления для User.

Например:

* предоставлен доступ к Bot;
* завершена публикация Flow;
* завершена Broadcast;
* завершён импорт Bot;
* произошла критическая ошибка.

Notification является частью административной подсистемы и не заменяет бизнес-событие.

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* User видит только доступные ему Bot, за исключением явно разрешённого системного доступа;
* дочерний ресурс не может обойти BotAccess;
* создание Bot автоматически предоставляет доступ создателю;
* административные операции выполняются через Application;
* MoonShine не является источником бизнес-правил;
* удаление Bot не приводит к физическому удалению исторических данных в обычном процессе;
* критические операции аудируются.
