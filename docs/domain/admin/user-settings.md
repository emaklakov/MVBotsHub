# User Settings

**Документ:** `docs/admin/user-settings.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`UserSetting` содержит индивидуальные настройки административного интерфейса конкретного `User`.

Настройки относятся только к работе пользователя внутри MVBotsHub и не должны смешиваться с:

* `BotSettings` — настройками конкретного Bot;
* `MemberPreferences` — настройками участника Bot;
* системными настройками платформы.

---

# Ответственность

UserSetting отвечает за:

* персональные настройки интерфейса;
* предпочтения рабочего пространства;
* индивидуальные параметры отображения;
* другие настройки, относящиеся только к конкретному User.

UserSetting не отвечает за:

* права User;
* роли и permissions;
* доступ к Bot;
* настройки Bot;
* настройки BotMember;
* состояние административной Session;
* бизнес-логику платформы.

---

# Принадлежность

Каждый UserSetting принадлежит одному User.

```text
User
 │
 └── UserSetting
```

Для одного User используется один логический набор персональных настроек.

---

# Основные категории

В UserSetting могут храниться настройки:

```text
Interface
Workspace
Notifications
Localization
Other personal preferences
```

Конкретный набор параметров может расширяться.

---

# Настройки интерфейса

Могут хранить персональные предпочтения административной панели.

Например:

```text
sidebar_collapsed
compact_tables
show_statistics
```

Такие значения влияют только на отображение UI.

---

# Рабочее пространство

User может иметь собственные настройки рабочего пространства.

Например:

```text
last_selected_bot
last_selected_section
saved_filters
saved_table_columns
```

Эти значения являются удобством интерфейса и не предоставляют пользователю дополнительных полномочий.

Например:

```text
last_selected_bot = bot-15
```

не означает, что User получает доступ к `bot-15`.

Доступ всегда проверяется через `BotAccess` и permissions.

---

# Уведомления

UserSetting может содержать предпочтения отображения административных уведомлений.

Например:

```text
show_success_notifications = true
show_background_notifications = true
```

Настройки каналов доставки уведомлений, если они появятся, должны быть отделены от самого объекта Notification.

---

# Язык административного интерфейса

При необходимости UserSetting может содержать язык административного интерфейса.

Важно отличать:

```text
UserSetting.locale
```

от:

```text
Bot.default_language
```

и:

```text
BotMemberPreferences.preferred_language
```

Это три разных контекста языка:

```text
User
  ↓
язык админки

Bot
  ↓
язык по умолчанию для участников

BotMember
  ↓
индивидуальный язык общения с Bot
```

---

# Фильтры и таблицы

UserSetting может хранить персональные настройки административных таблиц.

Например:

```text
Bots table
→ visible columns
→ sort
→ filters
```

Такие настройки не должны влиять на серверную авторизацию или фактический набор доступных записей.

---

# Изменение UserSetting

User может изменять разрешённые персональные настройки через административный интерфейс.

Общий поток:

```text
MoonShine
   ↓
UpdateUserSettings
   ↓
UserSetting
```

Если изменение не содержит бизнес-правил, оно может быть простым Application Use Case.

---

# Настройки, связанные с безопасностью

Настройки безопасности не должны автоматически храниться в UserSetting только потому, что они персональные.

Например:

* пароль;
* MFA secrets;
* recovery codes;
* authentication tokens;

относятся к соответствующему механизму безопасности и должны храниться в защищённом контексте.

UserSetting предназначен для пользовательских предпочтений, а не для секретов.

---

# Доступ администратора к UserSetting

Обычный User должен иметь возможность изменять только собственные UserSetting.

Просмотр или изменение настроек другого User требует отдельного административного permission, если такая возможность вообще необходима.

Например:

```text
user.settings.view
user.settings.manage
```

Скрытие раздела в UI не заменяет серверную проверку.

---

# Влияние на User

Изменение UserSetting не изменяет:

* глобальные permissions;
* роли;
* BotAccess;
* Bot;
* Person;
* BotMember.

Например:

```text
UserSetting.locale = en
```

не изменяет язык общения пользователя с Telegram Bot.

---

# Удаление и восстановление

UserSetting не должен существовать независимо от User.

При блокировке User настройки сохраняются.

При архивировании User настройки сохраняются вместе с User.

Отдельное физическое удаление UserSetting обычно не требуется.

---

# Кэширование

Часто используемые UserSetting могут кэшироваться.

Кэш не является источником истины.

После изменения настройки соответствующий кэш должен инвалидироваться.

---

# Безопасность

UserSetting может содержать персональные предпочтения User.

Поэтому:

* другой User не должен получать к ним доступ без permission;
* настройки не должны использоваться для обхода авторизации;
* секреты не должны храниться в UserSetting;
* экспорт административных данных должен учитывать privacy policy.

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* UserSetting принадлежит одному User;
* UserSetting не определяет permissions;
* UserSetting не определяет BotAccess;
* UserSetting не хранит BotSettings;
* UserSetting не хранит MemberPreferences;
* персональная настройка не предоставляет дополнительных прав;
* язык административного интерфейса не связан с языком BotMember;
* секреты аутентификации не хранятся как обычные UserSetting.

---

# Будущие возможности

Архитектура допускает расширение UserSetting:

* персональные dashboard;
* сохранённые представления;
* пользовательские shortcuts;
* настройки плотности интерфейса;
* настройки уведомлений;
* персональные фильтры;
* настройки часового пояса административного интерфейса.

Новая настройка должна добавляться сюда только в том случае, если она относится к удобству конкретного User и не является бизнес-настройкой Bot или участника Bot.
