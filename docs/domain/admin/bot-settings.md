# Bot Settings

**Документ:** `docs/admin/bot-settings.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

Настоящий документ описывает административное управление настройками конкретного `Bot`.

Бизнес-модель `BotSettings` описана в:

`docs/domain/bot-settings.md`

Настоящий документ определяет только административный интерфейс и сценарии изменения настроек.

---

# Контекст Bot

Все настройки изменяются в контексте выбранного Bot.

```text
MVBotsHub
    ↓
Bot
    ↓
Settings
    ↓
BotSettings
```

Перед изменением проверяется:

```text
Authenticated User
        ↓
Global Permission
        ↓
BotAccess
        ↓
Bot Settings Permission
        ↓
Bot belongs to current context
        ↓
Update
```

---

# Доступ

Для просмотра настроек используется permission, например:

```text
bot.settings.view
```

Для изменения:

```text
bot.settings.update
```

User без соответствующего permission не должен иметь возможности изменить настройки через API или прямой административный маршрут.

---

# Общие настройки

Административный интерфейс может предоставлять группы настроек по смыслу.

Например:

```text
General
Localization
Conversation
Flow
Broadcast
```

Группировка является частью UI и не должна менять ответственность `BotSettings`.

---

# Языки

В разделе Localization администратор может определить:

* поддерживаемые языки Bot;
* язык по умолчанию;
* политику обязательности переводов.

Например:

```text
Поддерживаемые языки:

✓ Русский
✓ English
✓ Қазақша
```

```text
Язык по умолчанию:
Русский
```

Подробные правила описаны в:

`docs/domain/localization.md`

---

# Политика локализации

В административном интерфейсе может быть доступна настройка:

```text
Требовать полный перевод перед публикацией
```

Например:

```text
ON
```

означает, что `FlowCompiler` может блокировать публикацию при отсутствии обязательных переводов.

Саму проверку выполняет Domain/Application, а не UI.

---

# Conversation

В разделе Conversation администратор может видеть и изменять разрешённые глобальные параметры.

Основное бизнес-правило текущей архитектуры:

```text
30 календарных дней без активности
```

после чего Conversation закрывается автоматически с причиной:

```text
Inactivity
```

Если в будущем период станет изменяемой настройкой Bot, административная форма должна валидировать допустимый диапазон и не изменять исторические Conversation.

---

# Часовой пояс

Bot может иметь часовой пояс, используемый по умолчанию для операций, связанных со временем Bot.

Например:

```text
Asia/Almaty
```

Часовой пояс Bot не изменяет уже зафиксированные исторические даты и время.

Если пользовательский часовой пояс разрешён, он хранится в `MemberPreferences` и имеет приоритет над BotSettings.

---

# Настройки Flow

Администратор может управлять только настройками, относящимися ко всему Bot.

Настройки конкретного сценария должны изменяться в самом `Flow` и его связанных сущностях.

Например:

```text
BotSettings
→ политика публикации и локализации

Flow
→ настройки конкретного сценария
```

---

# Настройки Broadcast

Глобальные политики Broadcast могут задаваться на уровне Bot.

Настройки конкретной рассылки должны редактироваться внутри `Broadcast`.

Например:

```text
BotSettings
→ общие ограничения

Broadcast
→ аудитория, содержимое, расписание
```

---

# Системные сообщения

Системные сообщения Bot редактируются в контексте настроек Bot.

Например:

```text
bot.welcome
bot.unknown-command
bot.phone-request
bot.error
```

Для каждого системного сообщения могут отображаться:

```text
Основной текст
Переводы
```

Пользователь не должен переходить в отдельный раздел Localization.

---

# Редактирование

Изменение BotSettings выполняется через Application Use Case.

```text
MoonShine
    ↓
UpdateBotSettings
    ↓
Domain
    ↓
BotSettings
```

Обычная форма MoonShine не должна самостоятельно выполнять сложные бизнес-правила.

---

# Сохранение

Изменения настроек должны быть валидированы до сохранения.

Например:

* выбранный язык существует;
* язык включён в список поддерживаемых;
* часовой пояс корректен;
* значение настройки допустимо;
* User имеет право изменить соответствующую настройку.

---

# Влияние на BotMember

Изменение BotSettings не должно автоматически переписывать `MemberPreferences`.

Например:

```text
Bot default language = ru
```

может стать:

```text
Bot default language = kk
```

но участник с:

```text
preferred_language = en
```

не должен автоматически получить `kk`, если `en` остаётся поддерживаемым.

---

# Влияние на Flow

Изменение BotSettings может влиять на последующие операции публикации и выполнения, но не должно изменять уже опубликованные `FlowVersion`.

Например:

```text
Изменили политику локализации
        ↓
Новые публикации проверяются по новой политике
```

Исторические версии Flow остаются неизменными.

---

# Влияние на Broadcast

Новые Broadcast используют актуальные настройки Bot.

Уже выполняющийся или завершённый Broadcast не должен изменяться задним числом только из-за изменения BotSettings.

---

# Массовые изменения

Изменение настроек, способных существенно повлиять на поведение Bot, может требовать дополнительного подтверждения.

Например:

```text
Изменить язык по умолчанию
Изменить обязательность локализации
Изменить режим работы Bot
```

Повторное подтверждение является UI-механизмом, но серверная авторизация остаётся обязательной.

---

# Аудит

Изменения BotSettings должны фиксироваться в административном аудите.

Минимально:

```text
User
Bot
Setting
Old Value
New Value
Date / Time
Result
```

Особенно важны изменения:

* языка по умолчанию;
* поддерживаемых языков;
* политики публикации;
* режима работы Bot;
* настроек, влияющих на массовые операции.

---

# Уведомления

Некоторые изменения могут создавать административное Notification, если изменение запускает длительную или асинхронную операцию.

Например:

```text
Settings updated
Cache refresh completed
```

Notification не является заменой аудита.

---

# Кэширование

BotSettings могут кэшироваться для быстрого доступа runtime-компонентов.

При изменении настройки соответствующий кэш должен быть инвалидирован.

Кэш не является источником истины.

---

# Безопасность

Нельзя считать скрытие поля или раздела достаточной защитой.

Каждый запрос на изменение должен повторно проверять:

```text
User
 ↓
Global Permission
 ↓
BotAccess
 ↓
Operation Permission
 ↓
Update
```

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* настройки изменяются только в контексте конкретного Bot;
* User без соответствующего доступа не может изменить BotSettings;
* пользовательские настройки не хранятся в BotSettings;
* настройки конкретного Flow не хранятся в BotSettings без необходимости;
* изменение BotSettings не переписывает MemberPreferences;
* изменение BotSettings не изменяет исторические FlowVersion;
* изменение BotSettings не изменяет историю уже завершённых Broadcast;
* критические изменения аудируются;
* UI не является единственным уровнем безопасности.
