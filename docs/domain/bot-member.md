# BotMember

**Документ:** `docs/domain/bot-member.md`

**Версия:** 1.0

**Статус:** Draft

---

# Назначение

**BotMember** представляет участие конкретного Person в конкретном Bot.

BotMember является связующим звеном между Person и Bot и хранит все данные, относящиеся исключительно к взаимодействию человека с данным ботом.

Один Person может иметь несколько BotMember — по одному для каждого Bot.

---

# Ответственность

BotMember отвечает за:

- связь Person с Bot;
- хранение текущего `telegram_id`;
- хранение текущего `chat_id`;
- выбранный язык общения;
- состояние регистрации;
- статус участника;
- дату последней активности;
- пользовательские настройки, относящиеся только к данному Bot.

BotMember НЕ отвечает за:

- хранение персональных данных человека;
- настройки Bot;
- историю сообщений;
- выполнение сценариев;
- массовые рассылки.

---

# Основные обязанности

BotMember должен обеспечивать возможность:

- регистрации человека в Bot;
- повторного входа после смены `telegram_id`;
- обновления данных Telegram;
- выбора языка общения;
- хранения состояния участия в Bot;
- получения текущего статуса участника.

---

# Инварианты

## Уникальность

Для одной пары `(Bot, Person)` может существовать только один BotMember.

---

## Принадлежность

Каждый BotMember принадлежит ровно одному Bot.

---

## Связь с Person

Каждый BotMember обязательно связан с одним Person.

---

## Независимость

Изменения BotMember не влияют на другие BotMember этого же Person.

---

## Актуальность Telegram

BotMember хранит только актуальные технические данные Telegram.

При изменении `telegram_id` или `chat_id` информация обновляется без создания новой записи.

---

# Жизненный цикл

```text
Первое сообщение

↓

Ожидание телефона

↓

Телефон подтверждён

↓

Активен

↓

Заблокирован (опционально)

↓

Архивирован (опционально)
```

До подтверждения телефона BotMember считается незавершённым.

---

# Первичная регистрация

При первом обращении пользователя выполняется следующий сценарий.

```text
Пользователь пишет Bot

↓

Создаётся временный BotMember

↓

Bot запрашивает контакт

↓

Пользователь отправляет номер телефона

↓

Поиск Person

↓

Person найден?
        │
   ┌────┴────┐
   │         │
 Да         Нет
   │         │
   ▼         ▼
Связать   Создать Person
   │         │
   └────┬────┘
        ▼
BotMember становится активным
```

Таким образом идентификация человека выполняется исключительно по номеру телефона.

---

# Повторная регистрация

Если пользователь удалил Telegram-аккаунт или получил новый `telegram_id`:

1. пользователь снова начинает диалог с Bot;
2. Bot запрашивает номер телефона;
3. система находит существующий Person;
4. обновляются `telegram_id` и `chat_id`;
5. создаётся новая связь с Telegram без создания нового Person.

История взаимодействия сохраняется.

---

# Связи с другими модулями

| Модуль | Тип связи |
|---------|-----------|
| Bot | Многие к одному |
| Person | Многие к одному |
| Conversation | Один ко многим |
| FlowSession | Один ко многим |

BotMember не имеет прямой связи с Broadcast.

---

# Основные сценарии использования

- регистрация нового участника;
- повторный вход;
- смена Telegram-аккаунта;
- смена языка;
- блокировка участника;
- восстановление участника;
- получение списка участников Bot.

---

# Ограничения

BotMember не хранит:

- персональные данные Person;
- настройки Bot;
- сообщения;
- сценарии;
- информацию о сотрудниках.

---

# Что BotMember НЕ делает

BotMember не отправляет сообщения.

BotMember не выполняет сценарии.

BotMember не принимает бизнес-решения.

BotMember не взаимодействует напрямую с Telegram API.

---

# Основные свойства

| Свойство | Описание |
|-----------|----------|
| Id | Уникальный идентификатор |
| BotId | Bot |
| PersonId | Person |
| TelegramId | Текущий Telegram ID |
| ChatId | Текущий Chat ID |
| Language | Выбранный язык |
| Status | Статус участника |
| RegisteredAt | Дата регистрации |
| LastActivityAt | Последняя активность |
| CreatedAt | Дата создания |
| UpdatedAt | Дата изменения |

Конкретная реализация хранения определяется инфраструктурным слоем.

---

# Масштабирование

Архитектура BotMember должна позволять:

- обслуживать миллионы участников;
- быстро находить участников конкретного Bot;
- быстро находить BotMember по паре `(Bot, Person)`;
- безопасно обновлять Telegram-идентификаторы без создания дубликатов.
