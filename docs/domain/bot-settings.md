# BotSettings

**Документ:** `docs/domain/bot-settings.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`BotSettings` содержит настройки, определяющие поведение конкретного `Bot` по умолчанию.

BotSettings является составной частью агрегата `Bot` и не существует независимо от него.

Настройки Bot применяются ко всем `BotMember`, для которых не задано отдельное пользовательское значение.

---

# Ответственность

BotSettings отвечает за:

* значения поведения Bot по умолчанию;
* настройки локализации уровня Bot;
* настройки поведения Conversation;
* настройки режима работы Bot;
* политики, общие для всех участников Bot;
* настройки, определяющие поведение Flow и других подсистем, если они относятся ко всему Bot.

BotSettings не отвечает за:

* персональные настройки пользователя;
* права User на Bot;
* текущее состояние BotMember;
* состояние FlowSession;
* историю Conversation;
* техническую реализацию Telegram API;
* настройки инфраструктуры приложения.

---

# Принадлежность

BotSettings существует только в контексте одного Bot.

```text
Bot
 │
 └── BotSettings
```

Для одного Bot используется один логический набор BotSettings.

---

# Основной принцип настроек

Настройки разделяются на два уровня:

```text
BotSettings
     │
     ▼
значение по умолчанию

BotMemberPreferences
     │
     ▼
индивидуальное значение
```

Если для конкретного BotMember существует пользовательское значение, оно имеет приоритет.

Если пользовательского значения нет, используется BotSettings.

---

# Категории настроек

BotSettings может содержать настройки следующих категорий.

## Основные

Определяют общее поведение Bot.

Например:

* режим работы;
* часовой пояс Bot;
* язык по умолчанию;
* параметры отображения.

---

## Локализация

Настройки, относящиеся ко всей локализации Bot.

Например:

* язык по умолчанию;
* поддерживаемые языки;
* требование полного перевода перед публикацией.

Подробные правила описаны в `docs/domain/localization.md`.

---

## Conversation

Настройки, влияющие на жизненный цикл Conversation.

Например:

* период неактивности до автоматического закрытия;
* разрешение автоматического завершения после окончания Flow;
* правила системного завершения.

Текущее утверждённое значение периода неактивности для Conversation — **30 календарных дней**.

---

## Flow

Настройки, применимые ко всему Bot и влияющие на выполнение сценариев.

Например:

* политика локализации при публикации;
* ограничения выполнения;
* глобальные runtime-параметры, если они действительно относятся ко всему Bot.

Настройки самого Flow должны храниться в `Flow` и его связанных сущностях, если они относятся только к конкретному сценарию.

---

## Broadcast

Настройки, общие для рассылок Bot.

Например:

* общая политика рассылок;
* ограничения;
* правила локализации;
* настройки, одинаковые для всех Broadcast данного Bot.

Настройки конкретной рассылки хранятся в `Broadcast`.

---

# Язык по умолчанию

`BotSettings` определяет язык по умолчанию Bot.

Например:

```text
default_language = ru
```

Язык по умолчанию используется, если:

* `BotMemberPreferences.preferred_language` не задан;
* выбранный язык больше не поддерживается Bot;
* политика системы требует fallback на язык Bot.

Изменение языка по умолчанию не изменяет пользовательские предпочтения уже существующих BotMember.

---

# Часовой пояс Bot

Bot имеет собственный часовой пояс, общий для всех участников, если иной часовой пояс не предусмотрен отдельной пользовательской настройкой.

Часовой пояс Bot используется для операций, связанных со временем Bot, например:

* расписаний;
* отображения дат;
* планирования Broadcast;
* системных операций, зависящих от локального времени Bot.

Часовой пояс не является свойством `Person`.

---

# Conversation Timeout

BotSettings определяет период неактивности, после которого Conversation считается завершённым.

На текущем этапе значение по умолчанию и принятое бизнес-правило:

```text
30 календарных дней
```

После истечения периода:

* текущий Conversation закрывается;
* фиксируется причина `Inactivity`;
* следующее сообщение пользователя приводит к созданию нового Conversation.

---

# Политика обязательной локализации

BotSettings может определять, требуется ли полный перевод локализуемого содержимого перед публикацией.

Например:

```text
require_complete_localization = true
```

Если политика включена, отсутствие обязательного перевода может заблокировать публикацию Flow.

Если политика выключена, используется fallback на исходное содержимое.

Конкретная проверка выполняется `FlowCompiler`.

---

# Режим работы Bot

BotSettings может определять режим общего поведения Bot.

Например:

```text
normal
maintenance
```

Точные состояния и правила их использования определяются агрегатом `Bot` и соответствующими Application сценариями.

BotSettings не заменяет жизненный цикл самого Bot.

---

# Разрешение значения

Для настроек, которые могут быть переопределены пользователем, используется следующий принцип:

```text
BotMemberPreferences
        │
        ▼
Есть пользовательское значение?
        │
   ┌────┴────┐
   │         │
  Да        Нет
   │         │
   ▼         ▼
User Value   BotSettings
```

Runtime-компоненты должны получать уже разрешённое значение, а не самостоятельно обходить уровни настроек.

---

# Effective Settings

В runtime может использоваться объект эффективных настроек, сформированный на основании:

```text
BotSettings
    +
BotMemberPreferences
    ↓
Effective Settings
```

Такой объект является временным представлением и не заменяет сами настройки.

---

# Изменение настроек

Изменение BotSettings должно выполняться через Application-сценарий изменения настроек Bot.

Непосредственное изменение внутреннего состояния из Presentation не допускается.

Например:

```text
MoonShine
   ↓
UpdateBotSettings
   ↓
Bot
   ↓
BotSettings
```

---

# Влияние на существующие BotMember

Изменение BotSettings не должно автоматически переписывать индивидуальные значения BotMemberPreferences.

Например:

```text
Bot.default_language = ru
```

изменён на:

```text
Bot.default_language = kk
```

Пользователь с:

```text
preferred_language = en
```

продолжает использовать `en`, если этот язык поддерживается Bot.

Пользователь без собственного языка начинает использовать новый язык по умолчанию `kk`.

---

# Влияние на существующие Conversation

Изменение настроек Bot не должно ретроспективно изменять уже завершённые Conversation или исторические данные.

Новые правила применяются к операциям после изменения настройки, если соответствующее бизнес-правило не требует иного.

Исторические факты не переписываются.

---

# Влияние на Flow

Настройки Bot могут влиять на публикацию и выполнение Flow, но не должны изменять опубликованный `FlowVersion` напрямую.

Например, изменение политики обязательной локализации может изменить возможность публикации нового FlowVersion, но не изменяет уже опубликованную версию.

---

# Влияние на Broadcast

Изменение общих настроек Bot не должно изменять исторические результаты уже выполненной рассылки.

Для новых Broadcast применяются актуальные значения настроек.

Если Broadcast уже перешёл к выполнению, его историческое содержимое и результаты доставки не должны изменяться задним числом.

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* BotSettings принадлежит одному Bot;
* для одного Bot существует один логический набор BotSettings;
* BotSettings содержит только значения, относящиеся ко всему Bot;
* пользовательские значения не хранятся в BotSettings;
* изменение BotSettings не переписывает BotMemberPreferences;
* Runtime не должен самостоятельно реализовывать каскад поиска настроек;
* эффективные значения могут вычисляться отдельно, но не становятся новым источником истины;
* BotSettings не зависит от Telegram API;
* исторические данные не переписываются изменением текущих настроек.

---

# Удаление

BotSettings не удаляется отдельно от Bot.

При архивировании или мягком удалении Bot его настройки сохраняются вместе с историей Bot.

Отдельное физическое удаление BotSettings не выполняется.

---

# Производительность

BotSettings используются часто, поэтому их чтение должно быть дешёвым.

Допускается кэширование настроек Bot.

Изменение настроек должно корректно инвалидировать соответствующий кэш.

Кэш не является источником истины.

---

# Безопасность

Настройки Bot могут содержать параметры, влияющие на поведение всей системы.

Изменять BotSettings может только `User`, имеющий соответствующее `BotAccess` и permission.

Секреты внешних систем не должны храниться в BotSettings, если для них существует отдельное защищённое хранилище credentials.

---

# Будущие возможности

Архитектура допускает расширение BotSettings новыми категориями, например:

* AI;
* аналитика;
* интеграции;
* ограничения;
* политики хранения;
* дополнительные каналы;
* настройки автоматизации.

Новая настройка должна добавляться только в том случае, если она действительно относится ко всему Bot. Индивидуальные настройки должны оставаться в `BotMemberPreferences`, а настройки конкретного Flow/Broadcast — в соответствующих агрегатах.
