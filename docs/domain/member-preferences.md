# MemberPreferences

**Документ:** `docs/domain/member-preferences.md`

**Версия:** 1.0

**Статус:** Актуален

---

# Назначение

`MemberPreferences` содержит индивидуальные настройки конкретного `BotMember`.

Эти настройки определяют персональное поведение Bot для одного участника и позволяют переопределять отдельные значения, заданные на уровне `BotSettings`.

`MemberPreferences` существует только в контексте конкретного `BotMember`.

---

# Ответственность

MemberPreferences отвечает за:

* индивидуальный язык общения;
* индивидуальные настройки, относящиеся к конкретному BotMember;
* значения, которые пользователь имеет право переопределять относительно BotSettings;
* пользовательские предпочтения, которые должны сохраняться между FlowSession.

MemberPreferences не отвечает за:

* глобальные данные Person;
* настройки самого Bot;
* права User на Bot;
* состояние FlowSession;
* историю Conversation;
* выполнение Flow;
* взаимодействие с Telegram API.

---

# Принадлежность

MemberPreferences принадлежит одному `BotMember`.

```text
Bot
  │
  ▼
BotMember
  │
  └── MemberPreferences
```

Для одного BotMember используется один логический набор индивидуальных настроек.

---

# Основные свойства

На концептуальном уровне MemberPreferences может содержать:

| Свойство                 | Назначение                                            |
| ------------------------ | ----------------------------------------------------- |
| preferred_language       | Предпочтительный язык участника внутри Bot            |
| timezone                 | Индивидуальный часовой пояс, если это разрешено Bot   |
| date_format              | Индивидуальный формат даты, если это разрешено Bot    |
| time_format              | Индивидуальный формат времени, если это разрешено Bot |
| notification_preferences | Индивидуальные настройки уведомлений                  |
| created_at               | Дата создания                                         |
| updated_at               | Дата изменения                                        |

Конкретный набор пользовательских настроек может расширяться.

---

# Предпочтительный язык

`preferred_language` определяет язык, выбранный пользователем для конкретного Bot.

Например:

```text
Person
   │
   ├── BotMember A
   │      └── preferred_language = ru
   │
   └── BotMember B
          └── preferred_language = en
```

Один Person может иметь разные языковые предпочтения в разных Bot.

Язык не является свойством Person.

---

# Эффективный язык

`preferred_language` является пользовательским предпочтением, но не гарантирует, что язык в данный момент поддерживается Bot.

Перед использованием значение проверяется относительно поддерживаемых языков Bot.

```text
MemberPreferences.preferred_language
                │
                ▼
       Язык поддерживается Bot?
             │
        ┌────┴────┐
        │         │
       Да        Нет / Не задан
        │         │
        ▼         ▼
Использовать   Bot.default_language
```

Если пользовательский язык не задан, используется язык по умолчанию Bot.

Если выбранный язык перестал поддерживаться, используется язык по умолчанию Bot, но само пользовательское предпочтение может быть сохранено.

---

# Изменение языка

Пользователь может изменить `preferred_language`, если выбранный язык поддерживается Bot.

Изменение языка:

* не изменяет Person;
* не изменяет другие BotMember этого Person;
* не изменяет BotSettings;
* не изменяет историю Conversation;
* применяется к последующим операциям общения.

---

# Язык по умолчанию

Если `preferred_language` отсутствует, используется `BotSettings.default_language`.

Изменение языка по умолчанию Bot не переписывает существующие MemberPreferences.

Например:

```text
Bot.default_language = ru
```

```text
MemberPreferences.preferred_language = en
```

После изменения `Bot.default_language` на `kk` пользователь продолжает использовать `en`, пока `en` поддерживается Bot.

Пользователь без собственного языка начинает использовать `kk`.

---

# Часовой пояс

Если Bot разрешает индивидуальный часовой пояс, `MemberPreferences.timezone` может переопределять `BotSettings.timezone`.

Порядок разрешения:

```text
MemberPreferences.timezone
           │
           ▼
Значение задано и разрешено?
      │
 ┌────┴────┐
 │         │
Да        Нет
 │         │
 ▼         ▼
User TZ   BotSettings.timezone
```

Часовой пояс не является свойством Person.

---

# Формат даты и времени

Если Bot предоставляет возможность персонального форматирования даты и времени, соответствующие значения могут переопределяться в MemberPreferences.

Это влияет только на представление данных и не изменяет фактические значения времени, хранящиеся в системе.

---

# Настройки уведомлений

Если Bot поддерживает пользовательские настройки уведомлений, они могут храниться в MemberPreferences.

Например:

```text
broadcasts = true
service_messages = true
marketing_messages = false
```

Конкретный набор параметров определяется функциональностью Bot.

---

# Только разрешённые переопределения

MemberPreferences не является копией BotSettings.

Только те настройки BotSettings, для которых явно разрешено пользовательское переопределение, могут иметь соответствующее значение в MemberPreferences.

Например:

```text
BotSettings.default_language
→ разрешено

BotSettings.timezone
→ может быть разрешено

BotSettings.conversation_timeout
→ не разрешено

BotSettings.require_complete_localization
→ не разрешено
```

Политика переопределения определяется настройками и бизнес-правилами конкретного Bot.

---

# Effective Settings

Во время выполнения может формироваться временное представление эффективных настроек:

```text
BotSettings
    +
MemberPreferences
    ↓
Effective Settings
```

Effective Settings не являются самостоятельным источником истины.

Исходные значения продолжают храниться в BotSettings и MemberPreferences.

---

# Использование в RuntimeContext

Во время выполнения Flow эффективные значения предоставляются через `RuntimeContext`.

Например:

```text
RuntimeContext.language
RuntimeContext.timezone
```

NodeHandler не должен самостоятельно искать BotSettings и MemberPreferences и вычислять приоритет значений.

Разрешение значений выполняется до использования их конкретным runtime-компонентом.

---

# Изменение настроек

Изменение MemberPreferences выполняется через Application-сценарий.

Например:

```text
Flow / Telegram / API
        ↓
UpdateMemberPreferences
        ↓
BotMember
        ↓
MemberPreferences
```

Presentation не должен напрямую изменять внутреннее состояние Domain.

---

# Изменение через Flow

Flow может изменять только те пользовательские настройки, которые разрешены политикой Bot.

Например:

```text
Пользователь выбирает язык
        ↓
Set Member Preference
        ↓
preferred_language = kk
```

После фиксации изменения последующие операции могут использовать новое эффективное значение.

---

# Изменение через административную панель

Администратор или другой User может изменять MemberPreferences только при наличии соответствующего права на конкретный Bot.

Изменение одного BotMember не должно изменять настройки других участников, если это не является отдельной массовой операцией.

---

# Изменение BotSettings

Изменение BotSettings не должно автоматически переписывать MemberPreferences.

Например:

```text
BotSettings.default_language = kk
```

не должно превращать:

```text
preferred_language = en
```

в:

```text
preferred_language = kk
```

---

# Отключение языка

Если язык, сохранённый в `preferred_language`, перестал поддерживаться Bot:

* значение `preferred_language` сохраняется;
* эффективным языком временно становится Bot.default_language;
* после повторного включения языка сохранённое предпочтение снова может стать эффективным.

Это позволяет не терять пользовательский выбор из-за временного отключения языка.

---

# Исторические данные

Изменение MemberPreferences не должно изменять исторические данные Conversation или Message.

Например, изменение языка сегодня не должно приводить к изменению языка уже отправленного сообщения в истории.

Исторические данные не переписываются.

---

# Жизненный цикл

MemberPreferences создаётся вместе с BotMember или при первом появлении пользовательской настройки.

Пустой набор настроек допустим: в таком случае для всех не переопределённых значений используются настройки Bot.

MemberPreferences не имеет самостоятельного жизненного цикла вне BotMember.

---

# Удаление

MemberPreferences не удаляется отдельно от BotMember.

При архивировании или мягком удалении BotMember состояние MemberPreferences следует его жизненному циклу.

Отдельное физическое удаление не выполняется в рамках обычного жизненного цикла.

---

# Инварианты

Всегда должны соблюдаться следующие правила:

* MemberPreferences принадлежит одному BotMember;
* настройки одного BotMember не влияют на другого BotMember;
* язык не является глобальным свойством Person;
* пользовательский язык хранится на уровне BotMemberPreferences;
* допускаются только явно разрешённые переопределения BotSettings;
* изменение BotSettings не переписывает MemberPreferences;
* неподдерживаемый язык может сохраняться как пользовательское предпочтение, но не используется как эффективный язык;
* эффективные значения вычисляются из актуальных источников;
* исторические Conversation и Message не изменяются из-за новых настроек.

---

# Безопасность

MemberPreferences являются пользовательскими данными.

Изменение настроек должно проходить через проверку принадлежности BotMember и соответствующих прав.

Особенно важно контролировать изменения из административной панели, Flow и внешнего API.

---

# Производительность

MemberPreferences могут использоваться при обработке практически каждого входящего события и выполнения Flow.

Для часто используемых данных допускается кэширование.

Кэш не является источником истины и должен корректно инвалидироваться при изменении настроек.

---

# Будущие возможности

Архитектура допускает расширение MemberPreferences такими настройками, как:

* валюта отображения;
* формат чисел;
* маркетинговые предпочтения;
* предпочтительный канал связи;
* настройки приватности;
* персональные параметры UX;
* дополнительные пользовательские предпочтения Bot.

Новая настройка должна добавляться сюда только в том случае, если она относится именно к конкретному BotMember и допускает пользовательское переопределение.
