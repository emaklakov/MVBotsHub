# Назначение

**Bot** — центральный агрегат предметной области MVBotsHub.

Bot представляет собой логическую модель Telegram-бота внутри платформы и является границей изоляции данных.

Каждый Bot полностью независим от остальных ботов.

Все данные, связанные с взаимодействием пользователей, сценариями, рассылками и настройками, принадлежат конкретному Bot.

---

# Ответственность

Bot отвечает за:

- собственную идентификацию;
- настройки работы;
- список поддерживаемых языков;
- управление участниками;
- выполнение сценариев;
- выполнение рассылок;
- создание диалогов;
- управление жизненным циклом бота.

Bot НЕ отвечает за:

- хранение сообщений;
- выполнение Flow;
- отправку сообщений в Telegram;
- хранение информации о сотрудниках;
- авторизацию пользователей административной панели.

---

# Основные обязанности

Bot должен обеспечивать возможность:

- создания нового бота;
- изменения основных параметров;
- включения и отключения бота;
- настройки поведения по умолчанию;
- хранения конфигурации;
- управления локализацией;
- управления сценариями;
- управления рассылками.

---

# Инварианты

Для каждого Bot должны соблюдаться следующие правила.

## Уникальность

Каждый Bot имеет уникальный идентификатор.

---

## Независимость

Данные одного Bot никогда не должны использоваться другим Bot.

---

## Изоляция

Все связанные сущности принадлежат только одному Bot.

Например:

- BotMember;
- Conversation;
- Flow;
- Broadcast;
- Localization;
- BotSettings.

---

## Консистентность

Удаление Bot должно выполняться только контролируемым способом.

Стратегия удаления определяется реализацией приложения.

---

# Жизненный цикл

Bot проходит следующие состояния.

```text
Создан

↓

Настроен

↓

Активен

↓

Приостановлен

↓

Архивирован (опционально)
```

Переходы между состояниями определяются бизнес-правилами приложения.

---

# Связи с другими модулями

Bot является владельцем следующих бизнес-модулей.

| Модуль | Назначение |
|----------|------------|
| BotSettings | Настройки бота |
| Localization | Поддерживаемые языки |
| BotMember | Пользователи бота |
| Conversation | Диалоги |
| Flow | Сценарии |
| Broadcast | Рассылки |

Доступ сотрудников к Bot определяется модулем **BotAccess**.

---

# Основные сценарии использования

Bot участвует в следующих сценариях.

- создание нового бота;
- подключение Telegram Bot API;
- настройка локализации;
- запуск сценариев;
- обработка входящих сообщений;
- выполнение рассылок;
- управление пользователями;
- получение статистики.

---

# Ограничения

Bot не хранит:

- сотрудников системы;
- права доступа;
- Telegram webhook;
- Telegram update;
- технические параметры очередей.

Эти данные относятся к другим подсистемам.

---

# Что Bot не делает

Bot не отправляет сообщения самостоятельно.

Bot не взаимодействует напрямую с Telegram API.

Bot не хранит состояние прохождения сценариев.

Bot не определяет права сотрудников.

Bot не управляет очередями.

---

# Основные свойства

На концептуальном уровне Bot содержит следующие данные.

| Свойство | Описание |
|-----------|----------|
| Id | Уникальный идентификатор |
| Name | Внутреннее название |
| Code | Уникальный системный код |
| Status | Текущее состояние |
| Settings | Настройки бота |
| SupportedLanguages | Поддерживаемые языки |
| DefaultLanguage | Язык по умолчанию |
| CreatedAt | Дата создания |
| UpdatedAt | Дата изменения |

Конкретная реализация хранения определяется инфраструктурным слоем.

---

# Границы агрегата

В агрегат Bot входят:

- Bot;
- BotSettings;
- Localization.

Следующие сущности являются самостоятельными агрегатами или отдельными модулями:

- Conversation;
- Flow;
- Broadcast.

Связь с ними осуществляется по идентификатору Bot.

---

# Правила доступа

Bot не содержит информации о владельце.

Доступ сотрудников определяется исключительно модулем **BotAccess**.

Один User может иметь доступ к нескольким Bot.

Один Bot может быть доступен нескольким User.

---

# Масштабирование

Архитектура Bot должна позволять:

- создавать неограниченное количество ботов;
- независимо изменять настройки каждого бота;
- независимо выполнять сценарии;
- независимо выполнять рассылки;
- независимо масштабировать обработку сообщений.
