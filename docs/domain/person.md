# Person

**Документ:** `docs/domain/person.md`

**Версия:** 1.0

**Статус:** Draft

---

# Назначение

**Person** представляет реального человека, взаимодействующего с платформой MVBotsHub через одного или нескольких Telegram-ботов.

Person является единой точкой идентификации пользователя независимо от количества ботов, с которыми он общается.

Один Person может одновременно являться участником нескольких Bot.

---

# Ответственность

Person отвечает за:

- идентификацию человека;
- хранение персональных данных;
- объединение нескольких Telegram-аккаунтов одного человека;
- связь с BotMember.

Person НЕ отвечает за:

- хранение telegram_id;
- хранение chat_id;
- выбранный язык;
- состояние общения;
- историю сообщений;
- выполнение сценариев;
- настройки конкретного бота.

Все перечисленные данные относятся к BotMember.

---

# Основные обязанности

Person должен обеспечивать возможность:

- регистрации нового человека;
- поиска существующего человека;
- изменения персональных данных;
- объединения нескольких Telegram-профилей одного человека;
- получения списка BotMember.

---

# Инварианты

Для каждого Person должны соблюдаться следующие правила.

## Уникальность

Каждый Person имеет уникальный идентификатор.

---

## Уникальность телефона

Телефон является основным способом идентификации человека.

В системе не может существовать двух Person с одинаковым номером телефона.

---

## Независимость от Telegram

Person не зависит от Telegram.

Удаление Telegram-аккаунта, смена `telegram_id` или повторная регистрация пользователя не приводят к созданию нового Person.

При повторном входе пользователь должен быть повторно связан с существующим Person по номеру телефона.

---

## Независимость от Bot

Person существует независимо от количества подключённых ботов.

Он может:

- не состоять ни в одном Bot;
- состоять в одном Bot;
- состоять одновременно в любом количестве Bot.

---

# Жизненный цикл

Person проходит следующие состояния.

```text
Создан

↓

Активен

↓

Архивирован (опционально)
```

Удаление Person допускается только контролируемым способом.

---

# Связи с другими модулями

Person взаимодействует со следующими модулями.

| Модуль | Тип связи |
|---------|-----------|
| BotMember | Один Person → много BotMember |

Прямых связей с Bot, Conversation, Flow и Broadcast Person не имеет.

Взаимодействие осуществляется через BotMember.

---

# Основные сценарии использования

Person участвует в следующих сценариях.

- первое обращение пользователя;
- повторный вход после удаления Telegram-аккаунта;
- смена Telegram-аккаунта;
- регистрация в новом Bot;
- обновление персональных данных.

---

# Ограничения

Person не содержит информации о конкретном Telegram-боте.

Person не содержит состояния диалогов.

Person не содержит информации о прохождении сценариев.

Person не содержит пользовательских настроек конкретного Bot.

Person не хранит технические идентификаторы Telegram.

---

# Что Person НЕ делает

Person не отправляет сообщения.

Person не получает сообщения.

Person не взаимодействует с Telegram API.

Person не хранит язык общения.

Person не хранит chat_id.

Person не хранит telegram_id.

Person не знает, какой сценарий сейчас проходит пользователь.

---

# Основные свойства

На концептуальном уровне Person содержит следующие данные.

| Свойство | Описание |
|-----------|----------|
| Id | Уникальный идентификатор |
| Phone | Номер телефона |
| FirstName | Имя |
| LastName | Фамилия |
| BirthDate | Дата рождения (опционально) |
| CreatedAt | Дата создания |
| UpdatedAt | Дата изменения |

Конкретная реализация хранения определяется инфраструктурным слоем.

---

# Особенности идентификации

Главным идентификатором Person является номер телефона.

При каждом обращении пользователя к Telegram-боту система должна:

1. определить текущий `telegram_id`;
2. получить номер телефона (если он ещё неизвестен);
3. найти Person по номеру телефона;
4. при необходимости создать нового Person;
5. обновить соответствующий BotMember.

Таким образом смена `telegram_id` не влияет на идентификацию человека.

---

# Масштабирование

Архитектура Person должна позволять:

- обслуживать неограниченное количество людей;
- связывать одного Person с любым количеством Bot;
- поддерживать повторную регистрацию без создания дубликатов.
