# Архитектурный стиль

MVBotsHub представляет собой **модульный монолит**.

Приложение разворачивается как единый сервис, однако состоит из независимых логических модулей с чётко определёнными границами ответственности.

Каждый модуль проектируется таким образом, чтобы его можно было развивать независимо от остальных модулей.

---

# Логическая архитектура

Архитектура приложения состоит из четырёх основных слоёв.

```text
                    ┌────────────────────────────┐
                    │        Presentation        │
                    └─────────────┬──────────────┘
                                  │
                                  ▼
                    ┌────────────────────────────┐
                    │        Application         │
                    └─────────────┬──────────────┘
                                  │
                                  ▼
                    ┌────────────────────────────┐
                    │           Domain           │
                    └─────────────▲──────────────┘
                                  │
                    ┌─────────────┴──────────────┐
                    │       Infrastructure       │
                    └────────────────────────────┘
```

---

# Назначение слоёв

## Presentation

Отвечает за взаимодействие с пользователями и внешними системами.

Примеры:

- MoonShine;
- HTTP API;
- Telegram Webhook;
- Console Commands.

Presentation НЕ содержит бизнес-логики.

---

## Application

Координирует выполнение сценариев использования (Use Cases).

Application:

- принимает запросы от Presentation;
- вызывает агрегаты Domain;
- обращается к репозиториям;
- публикует события;
- запускает фоновые задачи.

Application НЕ содержит правил предметной области.

---

## Domain

Содержит бизнес-модель платформы.

Domain определяет:

- агрегаты;
- сущности;
- Value Objects;
- доменные события;
- контракты репозиториев;
- бизнес-правила.

Domain является центральной частью архитектуры.

---

## Infrastructure

Реализует технические механизмы, необходимые для работы системы.

Примеры:

- PostgreSQL;
- Redis;
- Telegraph;
- файловое хранилище;
- внешние API;
- очереди.

Infrastructure реализует контракты, определённые в Domain.

---

# Основные модули предметной области

На текущий момент в системе выделены следующие бизнес-модули.

```text
Bot
│
├── BotAccess
├── BotSettings
├── Localization
├── Flow
├── Broadcast
├── Conversation
├── Message
├── BotMember
└── Person
```

Каждый модуль имеет собственную документацию в разделе `docs/domain`.

---

# Подсистема администрирования

Административная подсистема не является частью Domain.

Она включает:

- User;
- роли;
- разрешения;
- MoonShine;
- управление доступом сотрудников.

Документация расположена в разделе `docs/admin`.

---

# Поток выполнения запроса

Общий жизненный цикл обработки запроса выглядит следующим образом.

```text
Пользователь

↓

Presentation

↓

Application

↓

Domain

↓

Infrastructure

↓

Внешние сервисы / База данных

↓

Application

↓

Presentation

↓

Пользователь
```

Каждый слой отвечает только за свою часть обработки.

---

# Принцип зависимостей

Зависимости направлены к центру системы.

```text
Presentation
      │
      ▼
Application
      │
      ▼
Domain
      ▲
      │
Infrastructure
```

Domain не зависит от остальных слоёв.

---

# Внешние системы

На текущий момент система взаимодействует со следующими внешними компонентами:

- Telegram Bot API;
- PostgreSQL;
- Redis.

В дальнейшем список интеграций может быть расширен без изменения Domain.

---

# Масштабирование

Архитектура должна обеспечивать возможность:

- увеличения количества Telegram-ботов;
- увеличения количества пользователей;
- увеличения количества сообщений;
- увеличения количества рассылок;
- горизонтального масштабирования фоновых процессов.

Без изменения бизнес-модели.
