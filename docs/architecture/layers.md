# Назначение

Настоящий документ описывает логические слои архитектуры MVBotsHub, их ответственность и правила взаимодействия.

Слои определяют разделение обязанностей внутри приложения и являются основой для организации исходного кода.

---

# Общая схема

Архитектура приложения состоит из четырёх логических слоёв.

```text
                Presentation
                       │
                       ▼
                Application
                       │
                       ▼
                   Domain
                       ▲
                       │
               Infrastructure
```

Направление стрелок показывает допустимые зависимости.

---

# Presentation

## Назначение

Presentation отвечает за взаимодействие приложения с внешним миром.

Он принимает входящие запросы, преобразует их во внутренние команды приложения и возвращает результат.

---

## В Presentation входят

- HTTP Controllers
- Form Requests
- Middleware
- MoonShine
- Console Commands
- Telegram Webhook Controllers

---

## Presentation может

- валидировать входные данные;
- выполнять авторизацию;
- вызывать Application;
- преобразовывать DTO;
- формировать HTTP-ответы;
- отображать пользовательский интерфейс.

---

## Presentation не должен

- содержать бизнес-логику;
- обращаться напрямую к базе данных;
- обращаться напрямую к Telegram API;
- принимать бизнес-решения.

---

# Application

## Назначение

Application реализует сценарии использования системы (Use Cases).

Он координирует выполнение операций между Domain и Infrastructure.

---

## В Application входят

- Services
- Actions
- DTO
- Commands
- Queries

---

## Application может

- создавать и изменять агрегаты;
- вызывать доменные сервисы;
- работать с репозиториями;
- публиковать события;
- запускать фоновые задачи;
- управлять транзакциями.

---

## Application не должен

- содержать правила предметной области;
- зависеть от MoonShine;
- зависеть от HTTP;
- содержать SQL-запросы.

---

# Domain

## Назначение

Domain содержит бизнес-модель платформы.

Это центральный слой приложения.

---

## В Domain входят

- Aggregates;
- Entities;
- Value Objects;
- Domain Services;
- Repository Interfaces;
- Domain Events;
- Business Rules.

---

## Domain может

- изменять собственное состояние;
- проверять бизнес-ограничения;
- создавать доменные события;
- работать с Value Objects.

---

## Domain не должен

- зависеть от Laravel;
- зависеть от Eloquent;
- знать о PostgreSQL;
- знать о Redis;
- знать о MoonShine;
- знать о Telegraph;
- выполнять HTTP-запросы.

---

# Infrastructure

## Назначение

Infrastructure реализует технические детали работы приложения.

---

## В Infrastructure входят

- реализации репозиториев;
- интеграции с Telegram;
- Redis;
- PostgreSQL;
- файловая система;
- уведомления;
- кэш.

---

## Infrastructure может

- использовать Laravel;
- использовать Eloquent;
- использовать Telegraph;
- выполнять SQL-запросы;
- взаимодействовать с Redis;
- обращаться к внешним API.

---

## Infrastructure не должен

- содержать бизнес-правила;
- принимать бизнес-решения.

---

# Eloquent Models

Eloquent-модели располагаются в каталоге `app/Models`.

Они являются частью реализации хранения данных и не относятся к Domain.

Использование Eloquent-моделей внутри Domain НЕ ДОПУСКАЕТСЯ.

---

# MoonShine

Каталог `app/MoonShine` физически расположен в корне приложения.

Архитектурно MoonShine относится к слою Presentation.

Все ресурсы, страницы и формы MoonShine являются пользовательским интерфейсом административной панели.

---

# Laravel

Laravel является платформой для реализации приложения.

Компоненты Laravel используются только за пределами Domain.

Архитектура проекта не должна зависеть от особенностей конкретной версии Laravel.

---

# Взаимодействие слоёв

Допустимая последовательность вызовов:

```text
Presentation
      │
      ▼
Application
      │
      ▼
Domain
      ▲
      │
Infrastructure
```

Infrastructure реализует интерфейсы, определённые в Domain, и предоставляет данные слою Application.

---

# Типичный сценарий выполнения

```text
HTTP Request

↓

Controller

↓

Application Service

↓

Repository

↓

Domain

↓

Repository

↓

Eloquent Model

↓

PostgreSQL
```

После получения результата выполнение происходит в обратном порядке.

---

# Основные правила

- Каждый слой отвечает только за свою область ответственности.
- Каждый слой взаимодействует только с допустимыми слоями.
- Domain остаётся независимым от используемых технологий.
- Любая интеграция реализуется через Infrastructure.
- Presentation не содержит бизнес-логики.
- Application координирует выполнение сценариев использования.
- Infrastructure не принимает бизнес-решений.
