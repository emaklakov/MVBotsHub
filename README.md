# MVBotsHub

> Платформа для управления Telegram-ботами, сценариями общения и массовыми рассылками.

**Версия документации:** 1.0

---

# О проекте

MVBotsHub — это платформа для создания, управления и выполнения чат-ботов без необходимости программировать сценарии.

Основой системы является визуальный редактор, позволяющий собирать сценарии из готовых узлов, публиковать изменения и выполнять их одновременно для тысяч пользователей.

Платформа построена по принципам Domain-Driven Design (DDD) и имеет модульную архитектуру, позволяющую постепенно расширять функциональность без изменения существующих компонентов.

---

# Основные возможности

Система предоставляет полный набор инструментов для создания и сопровождения чат-ботов.

Основные возможности:

- создание неограниченного количества ботов;
- разграничение доступа пользователей к ботам;
- визуальный редактор сценариев;
- создание сложных сценариев без программирования;
- публикация новых версий сценариев;
- одновременная работа нескольких опубликованных версий;
- выполнение сценариев в реальном времени;
- тестирование сценариев в Sandbox;
- импорт и экспорт сценариев;
- поддержка нескольких языков;
- повторное использование сценариев;
- переходы между сценариями;
- журнал выполнения;
- сбор статистики;
- управление пользователями и ролями;
- управление правами доступа;
- система уведомлений;
- настройки платформы.

---

# Управление ботами

Каждый бот является самостоятельной единицей системы.

Для каждого бота можно:

- создавать сценарии;
- настраивать точки входа;
- подключать каналы связи;
- назначать пользователей;
- назначать роли и разрешения;
- управлять настройками;
- просматривать статистику;
- выполнять тестирование.

Пользователь видит только тех ботов, которые создал сам или к которым ему предоставлен доступ.

---

# Сценарии

Логика работы бота строится из независимых сценариев (Flow).

Каждый сценарий представляет собой отдельный процесс, который может запускаться различными способами.

Например:

- команда;
- ссылка;
- QR-код;
- API;
- переход из другого сценария.

Сценарии могут вызывать друг друга и возвращаться обратно после завершения.

---

# Визуальный редактор

Редактор позволяет создавать сценарии без написания кода.

Пользователь может:

- добавлять узлы;
- соединять их между собой;
- изменять параметры;
- использовать готовые шаблоны;
- тестировать сценарий;
- публиковать изменения.

Редактирование всегда выполняется в Draft.

Опубликованные версии остаются неизменными.

---

# Версионирование

Каждая публикация создаёт новую опубликованную версию сценария.

Это позволяет:

- безопасно изменять сценарии;
- сохранять историю публикаций;
- выполнять уже начатые сценарии без изменений;
- откатываться к предыдущим версиям.

---

# Выполнение сценариев

Для каждого пользователя создаётся собственная сессия выполнения.

Это позволяет одновременно выполнять один и тот же сценарий для большого количества пользователей без взаимного влияния.

Во время выполнения пользователь всегда работает с той версией сценария, которая была активна на момент запуска.

---

# Узлы сценария

Сценарий состоит из отдельных узлов.

Каждый узел выполняет одну конкретную задачу.

Например:

- отправка сообщения;
- ожидание ответа;
- выбор варианта;
- условие;
- цикл;
- вызов другого сценария;
- работа с переменными;
- выполнение HTTP-запроса;
- работа с файлами;
- интеграция с внешними сервисами.

Список узлов может расширяться без изменения архитектуры платформы.

---

# Работа с пользователями

Система поддерживает:

- пользователей;
- роли;
- разрешения;
- группы пользователей;
- персональные настройки;
- уведомления;
- журнал действий.

Все права доступа проверяются централизованно.

---

# Поддержка нескольких языков

Платформа позволяет создавать многоязычные сценарии.

Тексты сообщений, кнопок и других элементов могут храниться на нескольких языках.

Язык пользователя определяется автоматически или выбирается внутри сценария.

---

# Интеграции

Архитектура платформы предусматривает подключение различных каналов связи и внешних сервисов.

Например:

- Telegram;
- WhatsApp;
- Viber;
- Facebook Messenger;
- Instagram;
- VK;
- Slack;
- Discord;
- Web API;
- CRM;
- ERP;
- платёжные системы.

Добавление новой интеграции не требует изменения бизнес-модели системы.

---

# Безопасность

Платформа обеспечивает:

- разграничение прав доступа;
- контроль разрешений;
- журналирование действий;
- хранение истории публикаций;
- защиту от потери данных;
- безопасное тестирование сценариев в Sandbox.

---

# Масштабируемость

Архитектура системы позволяет:

- выполнять тысячи сценариев одновременно;
- подключать новые каналы связи;
- добавлять новые типы узлов;
- создавать собственные расширения;
- масштабировать выполнение сценариев;
- распределять нагрузку между несколькими серверами.

---

# Архитектура

Платформа разделена на несколько независимых слоёв.

```text
Presentation

↓

Application

↓

Domain

↓

Infrastructure
```

Каждый слой имеет собственную ответственность и может развиваться независимо.

---

# Основные принципы

При разработке платформы используются следующие принципы.

- Domain-Driven Design (DDD);
- SOLID;
- Clean Architecture;
- CQRS (при необходимости);
- неизменяемость опубликованных версий;
- расширяемость без изменения существующего кода;
- модульность;
- тестируемость;
- отказоустойчивость.

---

# Назначение платформы

MVBotsHub предназначен для создания современной платформы управления чат-ботами, которая позволяет разрабатывать сложные сценарии, поддерживать большое количество пользователей и каналов связи, а также постепенно расширять функциональность без изменения архитектурной основы системы.
